# K2 独立设备因素保护

> 状态：工程片已完成，Android 真机与正式验收待完成
> 日期：2026-10-03
> 基线：9bb28e5 与当前未提交 K1

人类要求继续尽快完成后续任务、避免过度测试。本片固定内部设备保护端口与 Android 原生实现，接通独立设备分支的 Header、reader、会话；不重复 K1 的全部互操作／原生矩阵，不自动迁移日常库。默认创建仍 v1，K3 恢复确认／新备份未完成前不切换。

设备端口只保护随机分支 B（32 bytes），不存 VMK。Android 使用独立 `liverelay.factor.v2.<reference>` Keystore AES-256-GCM key，reference 为随机 16-byte 小写 hex。每次 protect／unprotect 都须强生物识别 CryptoObject 授权；不允许设备 PIN、有效期内自动读取或旧 namespace 回退。nonce 12、密文 32、tag 16；AAD 为 Header factor AAD，最大 1024 bytes。取消、超时、后台／销毁、失效、不存在、失败返回受控错误；同一设备 adapter 操作串行，失败创建删除本次 key。Linux／Windows 返回明确未支持。

Header 保留 K1 suite 的精确字节，增加独立 `lr-or-recovery-device-v2-evaluation` suite。其三个分支固定 password、recovery、device；前两分支保持 K1，device 字段精确为 branchId/kind/deviceProfile/deviceReference/factorSlot/keySlot；profile `android-keystore-aes256-gcm-biometric-per-use-v1`。deviceReference 在 descriptor、全部 AAD 和整 Header MAC 中受保护，factorSlot 由原生端口封装 B，keySlot 仍由 B 派生用途密钥封装 VMK。两 suite 不交叉允许字段或静默替换。设备解封后验证整 Header MAC 才打开 SQLCipher。现有 epoch 策略变更仍要求全部保留凭证，留 K3 工作流，不用裸 bool 启用／禁用新格式。

本片允许拥有 core/ports、core/security、application/vault_session、infrastructure/security、app_composition、Android activity／adapter 及相关测试与 as-built 文档。无公共稳定契约变化、无 schema/Blob/归档版本变化、无依赖升级、无推送。AndroidX Biometric 使用现有依赖图中的 1.1.0 并显式声明直接依赖。

验证一次静态分析与完整回归，新增少量有意义的设备 OR／错误／篡改／取消边界验证，Android release 构建验证原生编译；若无连接设备，准确记录不能证明真机每次授权、录入失效和硬件密钥强度。K1 已通过的旧原生矩阵不重复跑。

实现与精确边界见 [设备规格](../../docs/30_design/security/09_设备因素保护与Header设备分支.md)。设备启用／禁用需收集保留凭证并重封装，本片接通原有解锁入口，不提前提供裸开关或默认生产创建。验证结果见 [K2 交付](../../handoffs/2026-10-03_K2设备因素保护.md)。
