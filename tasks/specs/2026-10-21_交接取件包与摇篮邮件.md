## 目标

把交接的默认路径从「接收者身份 + 完整指纹 + 逐条可见级别」收敛为「一个交接包按人分份，每份一个取件码；云端摇篮按预先写好的邮件把取件链接、WebDAV 账号密码、App 下载地址和留言发给接收者；接收者装 App、下载包、输取件码即可查看」。

本轮先跑通流程。身份绑定保留为严格模式，安全强化后置。

本任务取代 `docs/20_product/16_正式版演进与已确认范围.md` 中 2026-10-19「跨设备与云端取件仍走接收者身份」作为默认路径的决定；身份绑定不再是默认路径的前置条件。

## 本人已拍板的决策（2026-10-21）

1. 默认路径改为取件码包；接收者不需要身份、指纹或二维码。身份绑定保留为严格模式，后置。
2. 一个逻辑交接包，按接收者分份；云端物理上每人一份 `.lrshare`，界面显示为一个整体。
3. 邮件默认包含取件码；草稿在 App 内可看可改，删掉取件码也可以。
4. 邮件带 WebDAV 网址、账号、密码；本轮明确接受这个安全取舍。
5. 留言直接放邮件正文。
6. 取件码默认 App 生成；允许自定义，至少 12 位。
7. 取件码总览本轮只做显示/复制，不做导出/打印。
8. 接收者列表只在交接页维护；摇篮页只读显示 + 时间设置。
9. 第一版所有接收者共用同一个周期/提醒/宽限。
10. 本轮默认加入测试发送；App 下载地址默认 GitHub Releases，草稿可改。

## 用户流程

### 所有者

1. 交接页 →「交给他人」→ 添加接收者：称呼、邮箱。
2. 进入接收者详情：勾选内容（默认全选；6 档收进高级）、确认取件码、编辑邮件草稿。
3. 点「上传/更新交接包」：生成密码包，上传到 WebDAV；把启用中的接收者写进摇篮计划并上传。
4. 摇篮页设置周期、提前提醒、宽限，保存计划。
5. 到点后，摇篮服务按每位接收者的草稿发邮件。

### 接收者

1. 收邮件 → 点取件链接 → 用邮件里的 WebDAV 账号密码下载 `.lrshare`。
2. 下载/安装 LiveRelay。
3. 打开 App →「打开交接包」→ 选文件 → 输取件码 → 只读查看。

### 接收者详情

- 称呼、邮箱、状态。
- 内容：复选框；全选/清空；复制上一位的范围；共 N 条；「预览对方将看到的内容」。
- 卡片默认交付完整正文；密码条目默认交付账号、网址、备注和当前密码；原件默认不附，需在高级里单独勾选。
- 取件码：显示/复制/重新生成；自定义（≥12 位）；显示「邮件草稿是否包含取件码」。
- 邮件草稿：主题、正文；预览、编辑、重置为默认；留言是正文的一部分。
- 操作：上传/更新交接包、发送测试邮件、停用/启用、删除。

### 取件码总览

列表顶部按钮打开弹窗，列出所有接收者和取件码，默认遮住，可逐行显示/复制。本轮不做导出/打印。

### 摇篮页

- 保留：本人邮箱、周期、提前提醒、宽限、保存计划。
- 接收者名单改为只读，显示称呼、邮箱、启用状态；提供「去交接页管理接收者」。
- 删除「添加接收者」和逐人邮箱编辑，避免两份名单。

### 接收者入口

- 首次启动和解锁页增加「打开交接包」；选文件、输取件码、只读查看。
- 不需要创建接收者身份、输指纹或打开所有者资料库。
- 「我是接收者」身份路径保留，移到次要/严格模式入口。

```text

<留言>

取件链接：<WebDAV 文件地址>
云端账号：<账号>
云端密码：<密码>
取件码：<取件码>

LiveRelay 下载：<下载地址>

步骤：
1. 打开取件链接，输入上面的账号和密码，下载 <文件名>。
2. 安装 LiveRelay（如果还没装）。
3. 打开 LiveRelay，点「打开交接包」，选择下载的文件。
4. 输入取件码，查看内容。
```

- 取件码默认写入；用户在草稿里删掉后，详情页显示「邮件草稿不含取件码」，并提示需要另行告知。
- 改码/换码时，如果草稿里仍有旧码，提示一键替换。
- 下载地址默认 `https://github.com/BA2F/LiveRelay/releases/latest`，草稿可改；ECS 下载页后置。

## 数据格式

### 取件包

- 沿用本机交接的 `handoff-view` 信封：Argon2id 派生密钥，AES-256-GCM 加密；不新增密码学格式。
- 明文快照沿用 `snapshotFor` 的 `{version, records, originals}`，外层加 `ownerName`、`date`。
- 文件名使用 ASCII 短 ID：`liverelay-handoff-<8 位小写 base32>.lrshare`；称呼只在邮件和计划里出现，避免 URL 中文编码和重名。
- 本机交接文件与远程包共用同一格式；接收者「打开交接包」可打开两者。
- 取件码生成：12 位大写字母和数字，去掉易混字符，显示为 `XXXX-XXXX-XXXX`；输入时忽略空格和连字符。自定义允许任意字符，至少 12 位。

### 本机投递记录

存在 Vault 的本机加密值 `handoff.deliveries`：

```json
{
  "version": 1,
  "deliveries": [
    {
      "id": "d_...",
      "label": "妻子",
      "email": "wife@example.com",
      "packageName": "liverelay-handoff-a1b2c3d4.lrshare",
      "pickupCode": "K7Q2-9F3M-4T8P",
      "scope": [{"type":"card","id":"...","level":"full","history":false,"originalIds":[]}],
      "subject": "【留灯】张三 给你留了内容",
      "body": "...",
      "enabled": true,
      "uploadedAt": "2026-10-21T...Z",
      "updatedAt": "2026-10-21T...Z"
    }
  ]
}
```

### 摇篮计划 v2

在 v1 基础上，每个接收者增加 `subject`、`body`；保留 `label/email/package/cloudUrl/cloudUser/cloudPassword`。停用的接收者不写入计划。`version` 升为 2；服务端同时接受 v1（旧模板）和 v2（原样发送草稿）。

计划只有一个生成入口：读取本机投递记录 + 摇篮时间（周期/提前/宽限/本人邮箱），两个页面调用同一服务，不各存一份接收者名单。没设过时间用默认 7/1/3。

### 测试发送

App 写 `liverelay-cradle-test.json`：

```json
{"kind":"liverelay-cradle-test","version":1,"to":"...","subject":"...","body":"...","requestedAt":"..."}
```

服务端发送后写 `liverelay-cradle-test-result.json`（`requestedAt`、`sentAt`、`error`），App 读取并显示结果；测试不改变正式通知状态。默认发到本人邮箱；发到接收者邮箱需要二次确认。

## 服务端行为

- `notify_subject`/`notify_body`：接收者有 `subject`/`body` 就原样发送；没有就走 v1 旧模板。
- 处理测试文件：发送到 `to`，写结果文件；不影响 `notified`。测试文件独立处理，不依赖计划有效。
- 其余扫描、时间基准、提醒、去重逻辑不变。

## 状态与操作

| 操作 | 结果 |
| --- | --- |
| 新建接收者 | 状态「草稿」，生成取件码和默认草稿 |
| 上传/更新 | 包和计划都成功 →「已上传」；任一步失败 →「待更新」 |
| 改内容/取件码 | 需要重打包，状态「待更新」 |
| 改邮箱/草稿 | 状态「待更新」；第一版全量重传包和计划，后续再按需只传计划 |
| 停用 | 立即从计划移除并重传计划；失败要显著提示「计划未更新，仍可能发送」 |
| 删除 | 从计划移除、删除云端包、删除本机记录；删除前提示「如果邮件已经发出，收件人将无法下载」 |
| 重新生成/自定义取件码 | 生成新包文件名和新包，更新计划；旧包默认保留，旧邮件仍指向旧包和旧码。换码只影响之后发送的邮件，已下载副本无法收回 |
| 更换云端连接 | 所有投递记录标记「待更新」，提示重新上传 |

## 安全边界与已接受风险

- 邮件带同一个 WebDAV 账号密码；接收者能读客户卷里的 `liverelay-cradle-plan.json`，里面有其他人的邮箱、草稿和取件码。本轮接受。
- 云端当前是 IP+HTTP，WebDAV 账号密码在网络上明文；加密包内容不受影响。
- 取件码默认写在邮件和计划里；服务端能读到。想要服务端读不到，只能由本人另行告知，下一轮再做。
- 邮件发出、包被下载后无法撤回；换码/删除只能影响之后下载的副本。
- 下一步：每人一个只读账号或取件链接、HTTPS、发送状态回写、服务端不存取件码。

1. 所有者添加两位接收者，范围不同、取件码不同；两个包都上传，计划包含两份草稿。

7. 本机交接流程不受影响。
8. `flutter analyze` 无问题；新增单测/组件测试通过；服务端 v2 计划与测试发送干跑通过；ECS 真发一封到本人邮箱。

## 实现记录（2026-10-21）

- 包格式沿用 `handoff-view` 密码信封；新增 `HandoffViewService.encode`／`openBytes`，本机保存和远程上传共用。
- 新增 `PickupCode`：12 位无易混字符、分组显示；自定义至少 12 位，统一去空格/连字符并大写。
- 新增 `HandoffDelivery`／`HandoffDeliveryService`：本机加密值 `handoff.deliveries`，每位接收者一份范围、取件码、邮件草稿和上传状态；计划只包含 `status == uploaded` 的启用接收者。
- 交接页把「交给他人」列表放在最上面，本机取件区放在下面；手机上不用先滚过整份本机列表。新增「取件码总览」和 `RecipientDeliveryPage`（内容、高级范围、取件码、邮件草稿、预览、上传、测试发送、停用、删除）。
- 摇篮页接收者改为只读列表；保存计划前要求所有启用接收者都已上传，否则禁用保存并提示；云端旧计划接收者与本机列表不一致时给出警告。
- 计划升为 v2：每位接收者带 `subject`／`body`；服务端 v2 原样发送，v1 回退旧模板。新增 `liverelay-cradle-test.json` 与结果文件。
- 开屏解锁页只保留「打开交接包」、密码/生物识别解锁和「更多」；备份恢复、介质导入、密钥文件、独立恢复收进「更多」弹层。
- 接收者端：锁定页和首次启动只保留一个「打开交接包」入口；有本机交接时在底部弹层里再选「查看本机交接内容」。选文件、输取件码、只读查看；不需要身份、指纹或 Owner 资料库。接收者身份（严格模式）从锁定页和「我的」移到资料库设置 → 更多设置。
- 与设计稿的差异：
  - 本机投递记录多存一个 `message`，用于「从留言重新生成正文」；计划仍只带最终 `subject`／`body`。
  - 换码时生成新的包文件名，草稿里的旧包名和旧码一起替换，旧包保留；已发出的邮件仍指向旧包和旧码。
  - 测试发送要求先上传且没有未保存修改；结果文件带 `requestedAt`，App 只认最近一次请求。
  - `TransferMedium` 增加 `delete`；`CradleService` 增加 `deletePackage`。
  - 旧 `ManualHandoffPage` 不再从交接页进入，文件保留给后续严格模式入口。
- 验证：`flutter analyze` 无问题；`flutter test` 336 通过、3 跳过、0 失败；服务端 `CRADLE_DRY_RUN=1 CRADLE_ONCE=1` 实测 v2 草稿触发与测试邮件通过。
- 后续：严格模式 UI 整理、发送状态回写、每人只读账号或取件链接、HTTPS、ECS 下载页、浏览器直接取件页、旧 `ManualHandoffPage` 的去留。
