## 目标

按正式版交接建议，先完成多方式解锁、独立恢复凭证和接收者限定范围解密的安全设计，形成可评审的方案、内部契约候选、兼容与验收矩阵，再拆出实现任务。产品已确认方向不等于安全协议已确定；本规格不批准改写现有密钥或格式。

## 待定决策与设计工作

| 决策 | 必须提交的内容 | 尚未确认的边界 |
|---|---|---|
| 任一／全部解锁 | 支持的凭证组合、每种组合的成功／失败矩阵、密钥依赖关系、单因子及旧槽是否能旁路、设备能力不足时的处理 | 中文口令与自定密码均是知识凭证，不宣称两个独立因素；具体组合尚未冻结 |
| 自设密钥 | 比较自定密码、随机字符串与密钥文件的用途；定义输入、格式、编码、校验、导入及遗失处理 | “自设密钥”的文件形式与支持范围待定，不能默认为已有产品决定 |
| 独立恢复 | 凭证产生与熵依据、中文／非中文表达、备份介质、确认保存、恢复后重置／撤销、设备丢失路径 | 恢复是否绕过全部日常条件须明示并论证；当前中文日常口令不充当恢复凭证 |
| 所有者与接收者身份 | 稳定身份与授权凭证的关联、名称仅作显示、提前进入的可见信息、身份变更及密钥更换 | 当前 `recipientName` 不作为身份认证或密钥绑定证明 |
| 限定范围交接 | 明确接收者实际获得的数据、密钥与认证材料，涵盖所有释放层级、Secret、原件、来源链、历史、回收数据与组合成员 | 不能交付所有者 VMK；Secret 与原件的独立开关、多接收者及权限传播按领域定义所有者处理 |
| 条件与释放 | 区分本机模拟、真实身份认证、条件核验与信封投递；列出服务器、协助者及接收者的能力 | 无响应不等于身故；服务器提前投递能力及是否采用独立条件保障待论证 |
| 更新与撤销 | 说明策略缩减、凭证轮换、旧备份、旧信封、已交付明文与离线副本的处理范围 | 不把撤销未来访问描述为能够收回对方已经解密的信息 |

## 验收与验证要求

本设计任务不要求重复 Flutter 构建。必须完成以下文档与证据检查：

- 每个推荐方案有候选、采用／否决理由、代价、残余风险和反转条件；每个未定语义有明确决策项与影响。
- 每条核心安全要求都有方案对应点及后续验证项；实际实现、产品方向、候选契约和未验证假设分别标识。
- 任一／全部组合矩阵包括成功、少一凭证、错误凭证、不可用设备、取消操作和恢复；必须覆盖旧完整 VMK 槽是否造成旁路。
- 接收者矩阵按字段、记录和附件范围核对：默认隐藏、显示名不授权、其他接收者／其他库不可用、历史／回收／来源不越权、篡改／重放拒绝及授权改变后的旧包行为。
- 迁移／恢复矩阵覆盖现有中文与自定密码库、启用／禁用设备槽、旧 `.lvault`、未知／损坏格式，以及写入与目录替换各阶段中断；说明失败时原库和旧凭证的可用状态。
- 契约候选能支持独立实现与测试，未承诺尚未验证的跨平台密钥能力。链接与源码路径可定位，`git diff --check` 无本轮新增空白错误。

后续编码任务须明确自动测试与平台实测：原有创建／解锁与中文规范化回归；多槽组合、恢复、轮换与故障注入；隔离接收者实例对非授权数据确实不能解密；旧库／备份兼容；静态分析及完整 Flutter 测试。Android 真机和 Windows 验证单列，不能用替身测试或 Linux 构建代替。
