# 任务与多 Agent 协作规则

> 状态：当前有效  
> 版本：0.3  
> 最后更新：2026-09-06  
> 依赖文档：无


## 1. Task 是上下文编译结果

上层设计者负责把完整知识压缩成可执行 Task Spec。叶子 Agent 不需要理解整个项目，只需要：

- 自己要完成什么；
- 必读哪些文档；
- 依赖哪些契约；
- 允许/禁止改什么；
- 怎么验收；
- 什么情况必须向上反馈。

## 2. 看板

`tasks/看板.md` 是当前项目的人/AI 共用执行看板。小规模阶段使用一个文件的五个栏目：

- 待规划
- 待执行
- 进行中
- 已阻塞
- 已完成

任务量真实增长后再考虑拆文件或迁移到 Issues/Project 工具。

## 3. 模块文档按证据膨胀

简单模块可以只有一篇模块说明。真实详细设计出现后再增加 `详细设计.md`；测试要求达到独立维护价值后再增加 `测试与验收.md`。

复杂模块只有在内容拥有独立变化生命周期时继续拆。

## 4. 契约优先但不预造契约

跨模块并行的前提是稳定契约。契约文件至少应明确输入、输出、类型、错误语义、版本/兼容性和必要安全约束。

只有“recognize(image) → OCRResult”这种概念句时，它仍是候选，不应伪装成已存在的契约文件。

## 5. 文件所有权

Task Spec 应明确：

- 允许修改；
- 禁止修改；
- 不需要理解的模块；
- 相关契约；
- 验收和测试。

叶子 Agent 不得私自修改稳定公共契约或架构。

## 6. Handoff

真实任务完成、中止或阻塞后，记录：

- 实际完成；
- 修改文件；
- 测试结果；
- 与设计差异；
- 新问题/技术债；
- 是否需要契约/ADR变更；
- 下一步。

没有真实任务时不制造 Handoff。
