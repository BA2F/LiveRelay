# 决策与变更流程

> 状态：当前有效  
> 版本：0.3  
> 最后更新：2026-09-06  
> 依赖文档：无


## 1. 什么值得 ADR

只有需要长期保存“为什么”的重要、跨模块、难反转或高风险决策使用 ADR。

ADR 的价值是论证，不是数量。

一个合格 ADR 至少应包含：

- 背景和约束；
- 候选方案；
- 决策；
- 具体理由；
- 代价和风险；
- 被否决方案；
- 影响范围；
- 反转条件；
- 相关正式设计。

如果只有结论和套话，应标记为 `草案`。

## 2. 三类实现反馈

### 模块内部实现变化，契约不变
实现者可调整，更新详细设计和 Handoff。

### 稳定契约需要变化
Task → 已阻塞 → 变更说明 → 上层设计评审 → 更新契约/必要 ADR → 更新受影响任务 → 解阻。

### 长期架构决策失效
新证据 → 新 ADR → 旧 ADR 标记被替代 → 更新正式设计 → 拆迁移任务。

## 3. ADR 与设计必须互相引用

ADR 不能成为与 `docs/30_design/` 平行的孤岛。设计成熟时，应在“相关决策”中引用 ADR；ADR 也应指向对应正式设计。

当前仓库的早期 ADR 因论证过于模板化，已统一降级为草案，等待相关专题真正设计时补全。
