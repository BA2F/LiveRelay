## 日常使用与卡片

首次使用依次选择语言、外观和文字大小，然后创建资料库或恢复已有备份。创建需要设置解锁凭证，未来另提供独立恢复凭证；恢复已有库沿用其密钥体系。用户无需注册云账号即可本地使用。已有 MVP 资料库升级时直接解锁，不重新创建。

主导航为记录、卡片、密码库、交接、我的。密码卡片是信息卡片的专门子类型，未来可增加更多类型；密码库是同一份凭据的专门视图，不复制记录。默认遮盖密码，允许解锁后直接复制。通用卡片摘要与搜索不包含 Secret，也不因统一卡片就授权 Agent 读取密码。具体模型见 [账户与秘密](../30_design/domain/02_账户资产关系与秘密模型.md)。

“我的”承接身份、外观、安全、备份和供应商设置。身份由实际解锁权限决定：所有者与接收者不同，修改显示名称不改变权限。接收者可提前进入查看身份、交接进度；只有条件满足后才能获得相应资料的解密能力。当前 MVP 的本地接收者预览不等于接收者认证。

## 解锁与恢复

资料库使用随机主密钥，用户的凭证用于解封主密钥。中文口令、自设密码／密钥、设备生物识别可以成为不同解锁方式。用户未来可选择任一方式或要求全部方式；“全部”必须由密钥机制强制执行，不能只用界面检查。中文口令与自设密码都是知识凭证；生物识别授权设备保护的密钥，不把指纹当作可导出的密码。

2026-10-03 继续开发时已确认：日常默认任一方式解锁，密码可以单独解锁，已启用且设备可用的指纹也可以单独解锁，不强制密码＋指纹。未来的“全部方式”作为显式可选策略，须完成组合与迁移验证后提供。

独立恢复凭证支持随机中文词组，也支持随机的大小写字母、数字、符号组合，照顾非中文用户。已确认恢复凭证可绕过全部日常解锁条件，作为离线保管的最终恢复入口；持有它可恢复整库。本轮先保留自定密码，随机密钥文件及其字符串表达后置。恢复编码、设备遗失后的重置过程与文件格式仍需完成安全设计再实现。当前日常中文解锁口令不能标成已实现的独立恢复密钥。

交接凭证在概念上也是解锁凭证，但其解密范围由交接授权决定。向接收者交付整库主密钥后仅用界面隐藏不够。出生年份等易猜的密保问题不作为独立安全因子；是否增加辅助确认问题尚待评估。

首个真实交接切片已确认先支持本人明确授权、预览指定资料并手动交付给接收者；自动摇篮与条件释放后置。手动授权是独立真实授权，不借用本机模拟生命状态；具体身份绑定、字段与附件范围、接收者资料包契约仍须设计及验证。

2026-10-19 确认手动交接的交付节奏：接收者通常不在场，本人导入其公开身份、核对完整指纹并选好内容后打包；接收者在任何时间打开交接包时，由他的设备验证私钥。本人的交接准备页只保留"本人选择交付内容"这一件事，接收者身份验证不再占用本人页面的日常入口；本人身份页只展示本人资料与公开身份导出。

## Agent 与语音

先提供内置的简单 Agent：供应商 URL、API 密钥、模型配置；Responses 协议适配；受限命令工具与整理卡片的应用接口；结果先作为有来源的草稿。后续支持 OpenCode／Pi 等外部 Agent，以及 CLI／MCP。现有 MVP 的 Chat Completions 整理器不等于已实现上述 Agent。

桌面优先实现命令工具，Linux Bash 与 Windows 命令工具需要平台适配和实际隔离；仅设置工作目录不构成沙箱。手机保留同样入口，云端模型调用不因手机没有本地计算能力而必然不可用。未接入的工具显示实际状态。供应商插件不得得到主密钥或直接访问整库。

语音参考为 [DeepSeek Harness 官方可选语音输入模块](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/speech-to-text-sensevoice/README.md)（此前的 Hermes 称呼已更正）。保留本地语音提供者接口、模型下载／安装状态；手机模型可行性与实际内存占用后续测量。当前录音保存功能与语音转文字是不同能力。

## 摇篮服务、备份与服务器

本地优先。当前先使用定期导出的设备外冷备份；WebDAV 云盘已确认采用 copyparty（2026-10-13），部署资产与实测记录见 `work/deploy/copyparty/`，App 内"连接 WebDAV"页已完成（2026-10-14，设备间搬运页配置，凭证只存本机），并已部署到阿里云 ECS（2026-10-14，公网 `http://47.121.136.8:3923`，IP+HTTP 先行；形态＝1Panel 编排 + OpenResty 网关反代回环 copyparty，公网与内网均实测通过）。用户可使用托管服务，也可自部署 Docker；云介质走标准 WebDAV 子集，不另立协议。

摇篮流程为定期报平安、提醒、宽限期、用户预先授权的交接邮件。无响应不自动等于身故。服务器可发送封装为字符串的接收者加密交接凭证和必要调度信息，不能发送所有者主密钥或恢复凭证。服务器持有最终可投递信封时可能提前投递，是否需要独立条件保障另行设计。

未来 Docker 同时支持加密备份存储与摇篮邮件服务。结构化数据库和加密原始 BLOB 可分开上传：仅数据库、完整备份、后补原始附件。数据库也必须加密，不能把“文本”解释成上传明文。备份须以认证清单绑定库身份、密钥版本、附件标识和哈希；有意未包含附件与附件损坏必须区分。补充附件不是合并两份数据库编辑历史。所有者备份与限定范围的接收者资料包分开设计。

## 跨端、外观与调试

移动与桌面共享功能入口和业务含义，采用适合屏幕的布局。不可用功能保留入口，区分设备不支持、尚未接入、缺少模型、缺少配置和权限未授予。正常 UI 不加入开发说明；必要的功能状态和用户操作提示保留。

外观分为主题令牌、原子组件、业务呈现与可替换页面布局／档案浏览器。未来莱茵风格重点是正面三维抽出档案的交互和排版，不能只靠改颜色实现。先完善其他功能与内部呈现接口，再开发该外观；参考素材作为可选用户制作演示包，不默认分发。渲染器不访问数据库、主密钥或越权资料。接口先保持内部，不立即冻结第三方公共契约。

保存人类提供的参考：[RhineLabUI 仓库](https://github.com/LBEILC/RhineLabUI)、[在线演示](https://rhine.lubeiluchen.cc/)。

核心加密、鉴权、权限、迁移、恢复留在必需核心；供应商、语音、导入、备份目标与呈现可做扩展，不要求全部功能插件化。

调试演示采用独立构建入口、虚构资料库和可折叠悬浮控制面板，通过注入时钟、身份、状态和能力进行模拟。版本号连续点击只是调试构建的入口；发行构建应排除控制器与模拟资产。普通设置显式定义允许的选项，不自动继承调试开关。MVP 现有模拟页在完成这种隔离前必须清楚标识，不能伪装成真实在线交接。
