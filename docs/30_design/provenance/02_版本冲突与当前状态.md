# 版本、冲突与当前状态

> 状态：讨论中  
> 版本：0.6
> 最后更新：2026-09-19
> 依赖文档：provenance/00_来源追踪体系总览.md


## 本文是 Revision / Current State 的定义所有者

Domain 不再维护另一套“信息版本与可信度模型”。

## 当前结论

- 信息变化不能简单覆盖旧版本；
- 需要保留 Revision；
- 需要记录最后确认时间；
- 疑似过期时提示，但不删除历史；
- 正式文件、新口述和历史资料冲突时应并存并解释；
- 家属身故后补充的信息不能伪装成逝者本人原记录；
- AI 可以生成 Current State，但必须附来源和不确定性；
- Executor 默认可以先看当前状态，需要调查时再展开历史链。

同一对象的状态变化原则上更新同一张卡片并产生新 Revision，而不是建立无关卡片。例如房产证搬到新位置后，卡片的当前内容显示新位置，旧位置留在历史版本；不同对象或可独立理解的新事项才另建卡片。新旧 Revision 都应保留各自的时间与来源。

密码库条目的修改也保留加密的旧版本，包括旧密码；历史 Secret 默认不展示。普通删除不等于永久清除，用户需有明确操作清除当前 Vault 中该条目及其历史 Secret。已导出的独立备份不受当前 Vault 的清除操作控制，清除界面须说明这一点。

## 可信判断目前至少考虑

- 时间；
- 来源类型；
- 本人确认；
- 正式文件；
- 后续推翻；
- 冲突。

这些只是当前因素，不代表已经冻结评分算法。

## 当前开放问题

- Revision 数据结构；
- “当前版本”与“当前状态摘要”的区别；
- 冲突如何表示；
- 是否需要显式可信度分数；
- Current State 由规则、AI 还是混合方式生成。
