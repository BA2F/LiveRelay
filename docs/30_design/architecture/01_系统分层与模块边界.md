# 系统分层与模块边界

> 状态：已确认\
> 版本：0.6\
> 最后更新：2026-10-03\
> 依赖文档：architecture/00_系统架构总览.md


## MVP 实际分层

- 表现层 `lib/presentation/`：页面、交互、Material 3 主题和原子组件；
- 应用协调层 `lib/application/`：完整用例编排、解锁会话和 VMK 生命周期；
- 核心层 `lib/core/`：领域实体、生命周期规则、内部端口和不依赖 UI 的安全逻辑；
- 基础设施层 `lib/infrastructure/`：SQLCipher、文件、平台、OCR、网络 AI 和备份实现；
- 组合入口 `lib/main.dart` → `infrastructure/app_composition.dart`：集中创建默认实现并注入应用服务。

依赖方向为 `presentation → application → core`，基础设施实现 `core/ports` 并在组合根装配。当前是单 package 内的逻辑模块，不等于已冻结的跨 package 公共 API。

## 已确定的边界原则

- Vault 不理解资产、关系、死亡等业务语义；
- OCR 不决定权限；
- AI Provider 不直接读取数据库；
- UI 不直接写 SQL，也不实现密码算法；
- Life Core 不依赖具体 Flutter 插件；
- 页面按钮不应直接写 SQLite；
- OCR 不应绕过 AI Privacy 直接调用云 LLM；
- AI 相关模块不应获得 Master Key；
- Handoff 不应绕过 Vault 直接读取底层文件。

## 当前物理归属

- Application Owner：`AppController` 负责页面忙碌／错误状态、业务用例协调与解锁数据投影；
- Vault Session：`application/vault_session.dart` 负责 VMK 副本、密码／指纹、数据库会话、锁定清理和原件访问；
- Backup Workflow：`application/vault_backup_service.dart` 负责认证核对／导出／恢复，复用基础设施的归档与 K0 目录事务；
- Life Core：`core/domain`，包含实体和合法生命状态转换；
- Capture：表现层采集流程 + 基础设施媒体插件；原件统一进入 Blob/Vault；
- OCR：`OcrProvider` 端口和 Google ML Kit 实现，不掌握权限或 AI 配置；
- AI Privacy：`core/ai` 完成 Tokenization、校验和 Rehydration；网络 Provider 独立；
- Lifecycle/Handoff：领域规则在 `core/domain`，持久化和可见范围查询通过 Vault Repository；
- UI 不作为公共契约，领域/端口不得依赖 Widget。

## 2026-10-03 会话与恢复职责整理

AppController 通过具名注入接收会话、备份、AI／OCR、设置、导入器和环境准备函数；默认实例、SQLCipher Repository 工厂、设备路径、词表与缓存准备集中在 app_composition。控制器不持有 VMK、不创建数据库、不处理归档文件替换。页面接口保留，状态、Header 与指纹可用性通过只读投影获取。

VaultSession 只通过注入的 Repository 工厂和 VaultBlobStore 使用存储；VMK 仅由会话与备份应用服务持有，原件访问不给控制器传出 VMK。关闭数据库失败仍清除会话密钥，控制器 lock 的 finally 清除页面快照。备份先认证暂存，再关闭当前会话、安装并验证，成功后提交；启动恢复先于创建／解锁分流。

仍是单 package 的渐进分层：应用服务保留对当前归档／恢复错误与实现类型的引用，控制器保留现有 AI 设置与 CSV 导入类型；没有宣称基础设施类型全部反转为公共接口。现有端口与磁盘格式保持兼容；本轮不拆 package、不引入恢复凭证。

## 尚未冻结的边界

- 端口目前服务于本 App，不承诺第三方兼容或语义版本稳定；
- Capture 是否进一步形成独立 package，等待桌面端实现验证；
- 生命周期演示尚不包含现实身份、失能/死亡证明或远程交付信任链；
- 多设备同步、冲突合并和远程协作者不在当前物理架构内。
