# 系统架构总览

> 状态：讨论中  
> 版本：0.4  
> 最后更新：2026-09-06  
> 依赖文档：无


## 当前结论

LiveRelay 当前推荐采用 **Local-first 模块化单体 + 轻量 Clean Architecture**。

空间上的核心关系暂定为：

```text
UI
↓
Application
↓
Life Core
↓
Vault / Capture / AI Privacy / Handoff 等能力
↓
Database / Files / Cloud / OS
```

时间维度另外处理：

- 用户生命状态；
- 信息版本与修订；
- 信息释放状态；
- 来源历史。

当前逻辑能力候选包括：UI、Application、Life Core、Vault、Crypto、Database、Blob、Provenance、Capture/OCR、AI Privacy、AI Provider、Lifecycle、Handoff、Platform。

这里的“逻辑能力”不等于最终 Flutter 工程目录，也不等于已经冻结的物理模块。

## 知识所有权

- 模块边界与依赖规则：本架构子域；
- 业务实体、LifeState、Release Policy：`domain/`；
- Revision、来源、冲突、Current State：`provenance/`；
- Vault、密钥、数据库与 Blob 安全边界：`security/`；
- 人工字段标注类别：`capture/02_OCR坐标与人工字段标注.md`；
- AI Tokenization 与结构化处理：`ai/`；
- Executor/失能/身故流程：`handoff/`。

## 当前真正开放的问题

- Application 是否作为独立物理模块；
- Life Core 的实际边界；
- Capture 与 OCR 是一个模块还是两个；
- Lifecycle/Handoff 是否属于 Life Core 内部能力；
- 第一条 MVP 垂直链路如何映射为物理模块。
