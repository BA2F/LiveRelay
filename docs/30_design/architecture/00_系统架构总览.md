# 系统架构总览

> 状态：已确认\

## 当前结论

LiveRelay 当前推荐采用 **Local-first 模块化单体 + 轻量 Clean Architecture**。

当前单Flutter package内的依赖方向为：

```text
Presentation
↓
Application
↓
Core（领域、内部端口、安全与隐私逻辑）
```

Infrastructure实现Core内部端口，组合根集中装配SQLCipher、加密Blob、备份、Android设备因素、OCR、网络AI、本地语音和Linux命令隔离。用例由Application协调；UI和网络AI不取得VMK。当前运行链路含原生插件与FFI，云存储／摇篮／同步尚未进入实现。

时间维度另外处理：

- 用户生命状态；
- 信息版本与修订；
- 信息释放状态；
- 来源历史。

当前逻辑能力包括：UI、Application、Life Core、Vault、Crypto、Database、Blob、Backup、Provenance、Capture/OCR、AI Privacy、AI Provider、Lifecycle、Handoff、Platform。

当前 Flutter 路径映射见 `architecture/01_系统分层与模块边界.md`。逻辑能力已经落地，但仍不等于独立 package 或对外冻结模块。

## 2026-10 本机版架构基线

- VaultSession、VaultSecurityService和VaultBackupService承载解锁、换钥与恢复／备份流程；主界面新建Header v3、SQLCipher schema v5，旧库本人主动升级。
- Owner与Recipient保持独立身份、私钥和资料目录；LocalHandoffService按本人确认范围生成签名加密快照，接收者独立只读查看，不取得Owner VMK。真实手动交接与生命状态模拟分开。
- DraftAgentService调用受单次授权与Privacy Tokenization约束的Provider，结果由本人核对后保存；SpeechService使用本地SenseVoice并保留来源音频。Agent密码子类型录入尚未贯通。
- 正常入口与独立虚构演示入口分开；Android真机与Linux代表性链路已验证，Windows与正式签名／安全复核仍待验收。

可以依据此基线提交当前实现总体架构图。图应标明日期／源码版本、逻辑分层、数据与密钥所有权及外部服务信任边界；未来云端／同步／条件释放用明确的规划状态表示。该图不冻结全部内部端口、磁盘格式或未来整体系统方案。

## 当前真正开放的问题

- Application/Core 出现独立复用／发布需求后是否拆为独立 package；
- Capture 的平台插件部分与纯 Dart 工作流如何进一步分离；
- 本机真实手动交接已实现；远程传输、同步、生命状态核验将引入哪些新信任边界；
- 大文件流式加密与更多桌面安全能力如何扩展现有原生／FFI适配。
