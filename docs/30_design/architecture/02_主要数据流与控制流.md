## 当前核心数据流

### 采集与 AI 整理

```text
照片
→ 原图进入加密保存
→ 本地 OCR
→ 人工字段标记
→ Tokenization
→ 云 AI
→ JSON / Token 校验
→ 本地 Rehydration
→ 加密保存
→ Provenance
```

### 交接

```text
Vault 解锁
→ LifeState
→ Release Policy
→ Executor View
```

## 当前恢复原则

- 失败不能静默丢资料；
- AI/OCR 失败时保留原始资料；
- Token 不匹配时拒绝复原；
- 导出失败不能破坏原 Vault；
- 写入和迁移需要可恢复。

## MVP 已实现控制流

- 启动时读取非敏感 Vault Header；不存在则创建主密码/中文词组口令，存在则进入锁定页；
- 主密码经规范化和 KDF 解封 VMK，或由 Android 生物识别密钥槽授权读取 VMK，再打开 SQLCipher；
- 新增文字直接形成卡片；媒体原件先加密写入 Blob，再登记元数据和来源卡片；
- 图片解密到受控内存后交给本地 OCR，OCR 文本、行顺序、bbox 和置信度写回 Vault，只生成草稿；
- 用户按 OCR 行标记敏感类型，AI Privacy 本地 Tokenize，展示本次外发范围并获取单次授权；
- Provider 返回后先做 JSON/字段/Token 校验，再本地 Rehydrate，并以 AI 来源写入待确认草稿；
- 导出前再次验证主密码；恢复先在 staging 解包、校验清单和密码，再替换当前 Vault 并重新打开；
- LifeState 只允许合法演示转换，每次写事件；Deceased 不允许普通反向转换，演示重置走独立入口；
- Executor View 只按当前状态和 ReleasePolicy 投影允许内容，不绕过 Vault 读取文件。

## 当前未闭合控制流

- 崩溃或断电发生在 Blob 与数据库跨文件写入之间时的自动修复；
- 真实失能/身故核验、远程接收人认证和交付；
- 同步、冲突合并和多设备恢复；
- 正式发布环境中的密钥轮换与应用升级回滚。
