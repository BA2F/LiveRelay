## 本文是释放语义的定义所有者

其他子域可以引用这里的定义，但不要复制一套新的“可见层级”或策略公式。

## 当前可见层级

同一信息在不同条件下可以只释放不同层级：

1. 存在性；
2. 基本信息；
3. 完整内容；
4. Secret；
5. 原始资料。

## 当前策略表达

```text
信息 + 接收者 + 生命状态 + 条件 → 可见层级
```

这里表达的是**信息释放规则**，不是银行、证券、继承等法律授权。

默认策略是 Owner-only：新建卡片及原始资料均只对本人可见。向任何接收者在任何生命状态下释放存在性、基本信息、完整内容、Secret 或原始资料，都须由 Owner 明确设置。放进盒子或组合卡片仅改变组织和呈现，不会自动扩大成员卡片或原始资料的可见范围。Secret 和原始资料能否采用不同释放开关，需在详细策略模型中继续设计。

## MVP 策略实现

- 策略粒度为单张卡片或单条凭据；
- 每个记录当前最多一条策略，保存一个 `recipientName`；
- 策略分别保存 `INCAPACITATED` 和 `DECEASED` 的可见层级；
- 无策略时默认 `hidden`；`ACTIVE` 状态不进入 Executor View；
- 卡片支持 existence / summary / full 等层级；凭据只有达到 secret 层级才展示 Secret；
- 原始 Blob 尚未提供独立策略 UI，因此不能宣称首版已支持原件单独释放。

## 当前开放问题

- 多 Recipient/Policy；
- 除生命状态外的条件组合与优先级；
- Secret 与原始资料是否需要独立释放开关；
- 原始 Blob、组合卡片成员和来源链的权限传播；
- 接收人身份、角色和实际授权证明。
