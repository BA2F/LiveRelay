# LifeVault 导入导出与恢复

> 状态：已确认  
> 版本：0.8\
> 最后更新：2026-10-03\
> 依赖文档：security/02_LifeVault总体设计.md


## 当前原则

`.lvault` 导出文件必须适合存放在不可信介质，例如：

- U 盘；
- NAS；
- WebDAV；
- 普通备份空间。

需要考虑：

- 完整性验证；
- 防篡改；
- 格式版本；
- 损坏处理；
- 安全导入。

导出失败不能破坏当前运行中的 Vault。

## MVP 实现

- 导出前重新验证主密码，并用解封后的 VMK 生成清单认证码；
- 导出直接在内存中构建无压缩 ZIP bytes，再交给系统文件选择器保存；不会在 Vault 目录生成明文临时文件；
- 恢复先限制条目数和展开体积，拒绝目录、符号链接、重复/未知条目和路径穿越；
- 所有 payload 先写到独立 staging 目录，并校验大小、SHA-256 和 HMAC 清单；
- 使用导入 Vault Header 和用户密码解封其 VMK，再验证清单认证；
- 验证成功后才关闭当前数据库、替换目录并重新打开；异常时保留原 Vault；
- schema 迁移在恢复后的数据库打开阶段执行。

## 当前开放问题

- Android／Windows 文件系统的恢复中断实测，以及物理断电／目录持久化验证；
- 损坏 Blob 的局部恢复；
- “错误密码”和“文件损坏”的用户可理解但不泄漏细节的错误区分；
- 大型 Vault 的流式导入导出，避免内存中持有整个容器；
- 独立恢复工具和跨平台兼容测试样本。

## 2026-10-03 恢复事务修正

`VaultRestoreTransaction` 在经过密码、清单认证和数据库验证的 staging 替换前，写入本地恢复意图，成功打开安装后的数据库并读取数据后再提交独立完成标记。日志、incoming 与 rollback 都在运行库之外，目录名受限；启动不会按可篡改日志递归删除目录。

未提交恢复在有原库时保守回退并保留加密副本；首次恢复没有原库时，只沿日志中已验证的候选库继续，随后要求用户解锁。损坏日志、孤立候选或缺失必要文件进入恢复失败状态，不显示创建空库。提交后的清理失败不回退新库，保留加密残留并提示。

`RecoverableFile` 在 Header 替换前保留已 flush 的旧文件，缺失规范文件时恢复可校验的前序／暂存 Header；sidecar 以 `.tmp` 结尾，沿用现有归档排除规则。Header 输入限 64 KiB，拒绝符号链接与非普通状态文件。恢复后 Header 禁用生物识别，控制器也核对该状态，设备清理失败不读取旧设备 VMK。

Header／Blob／`.lvault` v1、schema v4 及密码／KDF 保持兼容。原生 Linux 跨进程退出已验证；进程退出通过不表示各平台物理断电已验收。独立恢复凭证和限定范围接收者包仍属于后续正式版实现。

## K1 版本边界

v1 归档创建与暂存读入显式要求 Header v1；Header v2 不能藏在同名 v1 外层，也不自动降级 Header。K1 v2 目前是独立底层评估，生产默认创建继续 v1；新备份／恢复确认与兼容矩阵交给 K3。失败导出通过现有工作流重新打开原会话，保留库与数据，已有 v1 恢复路径不变。

## 2026-10-13 设备间搬运（C 模式）

整库搬运以"用户选一个目录当介质"实现：U 盘、数据线、局域网盘、WebDAV 挂载目录对应用是同一件事。介质上数据库包固定名每趟重写，原件按卷只增不改，卷内清单与认证与既有 `.lvault` 一致；介质导出索引作为库内本地值随库搬运，接收端继承后往返只搬增量。快照标识改为随库稳定（vaultId+epoch 派生）：同一凭证血脉内的卷持续有效，换钥即整体作废、下次导出全量重来。

导入仍是整库替换、不做合并。认证通过后按导入库自己的日常策略分流：'any' 策略直接用该库自带凭证解锁并刷新页面（凭证随库走，不再强制换钥）；'all' 策略在本机无法满足，维持受限安全重设，重设完成后再从介质补齐原件卷。数据库包导入前先与当前库逐一比对省略清单的密文长度与 SHA-256，同内容原件就地复用，只把真正缺失的记入欠账；同钥补齐时密文直拷、不解密重加密，保证同一原件跨往返的描述符稳定。手机目录写不通时降级为多选文件导入、逐文件保存导出，并如实报告本次写了哪些、跳过了哪些。
