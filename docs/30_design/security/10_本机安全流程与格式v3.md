# 本机安全流程与格式 v3

> 状态：本机实现工程规格；不是已完成平台／安全验收
> 日期：2026-10-04
> 依据：安全 07／08／09；人类本机功能优先指令

独立 Header v3 suite `lr-owner-v3` 承载单密码、可选随机文件因素、可选设备因素，日常 any 为多个单因素分支，all 为一个 n-of-n 分支；恢复单独旁路。保留 v1／v2 reader，不改旧 evaluation 字节，不自动升级用户库。使用 v2 同样的固定 Argon2id 64 MiB／3／1 工程 profile；手机性能与真机授权仍需验收，不宣传为已完成正式安全认证。

顶层严格字段：formatVersion=3、suite、vaultId、headerEpoch、keyGeneration、createdAt、dailyPolicy、passwordKind、wordCount、biometricEnabled、keyFileEnabled、recoveryEnabled=true、branches、headerMac。ID、代次、时间、密码模式和 64 KiB／规范 ASCII JSON 限制沿用 v2。branches 为日常分支再恢复分支；每项 branchId、kind、factors、keySlot。因素严格为 factorId、kind、profile、salt／deviceReference、factorSlot。因素顺序 password、keyFile、device；OR 按此顺序分别建立分支；AND 仅 daily-all；恢复分支只有 recovery。盐 16、slot nonce 12／密文 32／tag 16，整 Header HMAC32；拒绝重复盐／nonce、任意 KDF 参数及未知 profile。

每分支随机 B32；n 因素生成 n-1 随机份额，最后 XOR 为 B。每份额独立在凭证派生钥或设备保护下封装；分支 HKDF(B,D,`LiveRelay/Header/v3/BranchKey/<branchId>`) 再封 VMK。descriptor 删除全部 factorSlot／keySlot／headerMac 后 SHA256 为 D。AAD 是规范数组 `["LiveRelay/Header/v3/<factor|master>",hex(D),branchId,factorId或空字符串]`。Recovery LRR1 保持原始随机 R，HKDF info 升为 `LiveRelay/Header/v3/RecoveryFactor`；随机文件因素精确 32 bytes、HKDF info `LiveRelay/Header/v3/KeyFileFactor`。Header MAC HKDF(VMK,vaultId,`LiveRelay/Header/v3/HeaderMac`) 覆盖去掉 headerMac 的完整规范图。

恢复进入受限流程，仅完成重新设置全部新日常材料与新 R、回输确认后转普通会话。设置更新重新生成份额／设备引用，旧设备引用提交后清理；任何凭证／策略变更都以新 VMK 在 staging 重建加密数据库并逐个重加密 Blob，保持逻辑 ID／修订／来源。复用 K0 的目录安装／回滚记录，验证新库和全部原件后提交，保留加密旧副本。旧备份可读旧资料，但旧 VMK 不能解开新数据。R 不自动复制日常口令，不在 Header／偏好／日志保存。

所有者备份新版本、独立接收者包与调试构建分别回写对应工程规格；不得把 v3 Header 塞进 v1 容器，或将 Owner VMK 交给接收者。

Android 设备因素在每次强生物识别成功回调中，对返回的授权 Cipher 依次执行 `updateAAD` 和 `doFinal`。不得在授权前提交 AAD：真机 Keystore 会缓存未授权错误并在 `doFinal` 报 `IllegalBlockSizeException`。平台通道解封结果视为借用且可能只读，适配层验证32字节并复制成自有可写数组，供核心统一清零；借用数组尽力清理，不保留引用，原生输出在编码后清零。设备取消／失效等类型错误保留到 UI，不归并为数据库错误。2026-10-04 小米13／Android13实测首次启用、已有库启用与换钥、指纹解锁及后台取消通过；未改变 suite、AAD 字节或 Header 格式，录入新指纹导致失效尚未实测。

本片主界面新建默认使用 v3；旧的 v1 创建方法为内部兼容／验证路径保留。schema v4→v5 只增加加密本地状态表，启动不自动改变旧 Header 或凭证。恢复 R 显示后要求单独保存勾选和完整回输；剪贴板复制后60秒尝试清理相同内容。设置切换会强制保存新 R，策略变更也会换 VMK。只恢复分层数据库后的缺失原件例外及补充解密钥处理见安全11；“全部原件已验证”的提交保证指本轮实际存在的原件，不把有意省略当作损坏。
