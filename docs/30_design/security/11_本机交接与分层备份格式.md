# 本机交接与分层备份格式

> 状态：本机实现工程规格；内部格式，未冻结为跨 package 公共契约
> 日期：2026-10-03
> 依据：安全 07／10、可见级别领域规则、人类本机功能优先指令

## 独立身份与信任

所有者身份资料（名称、联系方式、备注）、X25519／Ed25519 私钥、接收者绑定及交接计数保存在 SQLCipher schema v5 的 `vault_local_state`，随数据库备份和换钥迁移。名称可以更新，完整身份指纹不包含名称，也不会因为换日常密码而改变。名称和文件名不是权限证明。

接收者使用独立 `live_relay/recipient/` 目录、密码和身份，创建／导入／解锁入口在首次使用和锁定页即可到达；从所有者入口切换时先锁定 Owner。`.lridentity` 为固定 Argon2id 64 MiB／3／1 派生密码钥、AES-256-GCM 加密的独立私钥及信任／接收状态，salt16、nonce12、tag16；AAD 包含 version、suite、salt、明文长度。使用 RecoverableFile 的前序／pending 处理，文件上限 64 KiB；没有 Owner VMK、Owner 数据库路径或设备偏好。本人可导出加密身份备份并在另一独立目录用其密码恢复。遗失身份私钥及备份后不能凭名称找回已交付内容。

公开身份 `.lrpublic` 仅含 version=1、名称的 UTF-8 base64url、X25519 公钥、Ed25519 公钥。指纹为规范 ASCII 图 `{domain:LiveRelay/Identity/v1,encryptionKey,signingKey}` 的 SHA256，完整 64 位小写 hex。必须通过独立渠道核对并回输完整指纹。

2026-10-19 起，本机真实交接的默认形态是"交接视图 + 长期密码"，不再要求接收者身份文件或指纹核对。接收者与 Owner 在同一台设备上，Owner 在交接准备页选定内容并设置交接密码，接收者在锁定页输入该密码查看只读快照；Owner 的资料库保持锁定，接收者拿不到 Owner VMK。密码由双方共享，知道密码的人都能打开，这个路径只能证明"有人输对了密码"，不能证明接收者身份。

`.lrchallenge`／`.lrproof` 与 `.lrshare` 仍保留在服务和独立演示构建中：Owner 发出签名挑战（随机 challenge ID、Owner 公钥、接收者指纹、HPKE 加密随机32字节），接收者核对 Owner 指纹、验证签名、解密后签署响应（challenge ID／双方指纹／随机值），Owner 对照加密库内唯一待验证挑战和七天到期时间验证并消费。再次导入响应拒绝，重新生成挑战会替换先前待验证挑战。

接收者每次首次接收核对完整 Owner 指纹，持久化已验证 Owner 公钥和最高 sequence。显示名称不自动建立信任；恢复较旧的 Owner 备份可能重用旧 sequence，已接收较新包的接收端将拒绝较旧包。离线身份备份回退本身没有硬件单调计数保证，不把这个本地计数宣传为抗设备回滚的远程协议。

## 指定范围交接包

### 本机交接视图

文件固定为 `live_relay/handoff-view.json`，与资料库同目录、在 SQLCipher 之外。规范 ASCII JSON envelope：version=1、kind=`handoff-view`、salt16（base64url）、updatedAt、box{nonce12、cipherText、mac16}。密钥由共享密码经 Argon2id 64 MiB／3／1 派生 32 字节；AES-256-GCM 的 AAD 为除 box 外的 envelope 字段按规范 ASCII 排序编码。明文是 `version`、`records`、`originals`、`ownerName` 和 `date`，与 `.lrshare` 的记录字段相同，由同一个范围构建逻辑生成。

密码是长期的：每次保存沿用同一密码重新加密整份视图，更换密码即用新密码重写文件，旧密码随即失效。文件先写 `.tmp` 再经 `commitFile` 提交；读取不存在的文件或密码不对都不返回部分内容。接收者的只读页面与身份接收者共用同一套快照渲染。

`.lrshare` 是独立 v1 规范 ASCII JSON envelope：version、kind=scoped-delivery、随机 packageId16(hex)、Owner 公开身份、recipient 指纹、scopeEpoch=1、sequence、createdAt、scopeDigest、box、signature。当前本机手动交付没有自动权限撤销协议，scopeEpoch 暂固定为1。每次新封装使用新 ephemeral X25519 钥对和新 HPKE 会话；签名为 Ed25519，覆盖除 signature 外的完整规范 envelope。AAD 为除 box／signature 外的 header；scopeDigest 是实际 UTF-8 明文快照的 SHA256。HPKE info 为 `LiveRelay/ScopedDelivery/v1`；挑战使用不同 info `LiveRelay/IdentityChallenge/v1`。

HPKE 使用 [RFC 9180](https://www.rfc-editor.org/rfc/rfc9180.html) Base、DHKEM(X25519,HKDF-SHA256)、HKDF-SHA256、AES-256-GCM（KEM=0x0020、KDF=0x0001、AEAD=0x0002）。每次只有 sequence-zero 一条消息，没有上下文复用接口。KEM／KeySchedule 标签、kem_context=enc||pkR、info_hash／psk_id_hash、mode=0 和 nonce 均按该规格；拒绝零 DH。测试使用 [CFRG 公开向量](https://github.com/cfrg/draft-irtf-cfrg-hpke/blob/master/test-vectors.json) 的上述 suite，裁剪快照保存在 `test/fixtures/local_completion/hpke-base-aes256.json`，里面的私钥是公开测试材料。加密字节与其 ciphertext 一致，错误 AAD 和另一接收者私钥不能解密。

明文快照只含 version、records 和 originals。每条 record 包含 type／id／level／title／body／可选 secret／单独选择的 history／明确 originalIds。使用现有 ReleasePreview 的精确映射：卡片“基本信息”仍为正文前80个 UTF-16单元；密码“基本信息”只有名称、账号、网址，“完整内容”仅备注或账号，“含密码”才包含当前密码。记录历史必须另行勾选，卡片至少完整内容级别、密码至少含密码级别；不能借由摘要自动附带完整修订。原件仅允许卡片原件级别再逐个勾选，服务核对 cardSources 的归属；不展开来源链、关联卡片、回收区、其他账号或 Owner 数据库。

最多200条记录，原件总计64 MiB，明文快照128 MiB，wire180 MiB。接收端核验严格 envelope、签名、目标指纹、解密、摘要、记录字段、历史与原件范围；成功提交加密身份状态后才展示只读快照。packageId 去重、Owner sequence 高水位持久化，最多200个接收记录、64个受信身份，并受身份文件64 KiB总量限制。已验证包以密文保存在接收者目录；再次打开要求其 SHA256 与接收记录一致，不重新当成一次交付。当前密码及密码修订默认遮挡，原件须显式另存。接收者没有 Owner VMK，也不会打开或克隆 Owner 数据库。

本机生活状态模拟没有调用真实导出服务。真实交付始终逐次选择、核对输出并手动保存文件。已经交付的副本不能通过后来修改授权撤回；没有可信的离线时间锁、云端到达证明、摇篮自动触发或多设备合并协议。

## Owner 完整与分层备份

保留 `.lvault` v1 reader／writer，仍只接受 Header v1；Header v2 evaluation 保持拒绝。Header v3 使用容器 v2，MAC info=`LiveRelay/LifeVaultManifest/v2`，其余 ZIP 描述符／HMAC 原语和 K0 staging 安装继续复用。容器含 kind=full／database／attachments、snapshotId16(hex)、明文 vaultId，container 本身也是清单条目。snapshotId 自 2026-10-13 起由 vaultId+headerEpoch 派生：同一凭证血脉内稳定，换钥即变。attachments 卷可只携带 blobs 子集（设备间搬运按卷追加）。Header 与数据库必需；attachments 只需要 Header 与加密 Blob，不可作为完整库独立恢复。

数据库包和原件包在同一次暂停数据库的操作中导出，共用 snapshotId 和 Header，数据库包 manifest.omitted 精确列出有意省略的 Blob 相对路径、密文字节长度和 SHA256。完整包不得有 omitted；所有清单中实际存在的文件均必须通过描述符校验，重复条目、链接、非法路径、超出条目／展开体积、未知版本均拒绝。身份／钥代次由被 MAC 认证的 v3 Header 承载。包上限继续采用10000条目、展开2 GiB；现有实现按内存构建，资源优化后置。

备份导出可用当前密码认证；全部日常策略下，需要独立 R 进行便携备份认证。新格式恢复可以密码单分支或 R 认证；恢复后按导入库自己的日常策略分流——'any' 策略用该库自带凭证直接解锁并进入资料页面（凭证随库走，不强制换钥），'all' 策略在本机无法满足，进入受限安全重设，完成新密码／新 R 及全库换钥后才打开库。备份预览说明原件缺失数量与是否需要重设。设备引用不作为异机可用承诺。

数据库单独恢复时，先用 omitted 清单的密文长度与 SHA256 与当前库原件逐一比对，同内容原件在安装前就地复用、不计欠账；其余预期哈希、snapshotId 和原 Blob 解密钥存入加密数据库 `backup.missing`，不把旧钥写到外部 marker、偏好或日志。重设／换钥可以先处理数据库及现有原件，保留该加密缺失状态；未恢复原件的旧钥只为这一份旧附件补充使用，不能解开新数据。读取缺失原件给出明确提示。导入补充包（设备间搬运可按卷分次）时验证该旧钥的 manifest MAC、相同 snapshotId、包内每个在位原件的预期密文长度／SHA256；当前 VMK 与旧钥相同时密文直拷（描述符跨往返稳定），不同时解密核验后用当前 VMK 重加密；逐项清除缺失状态，包内未携带的欠件留在账上。不同备份组即使内容相同也拒绝；中途失败可重试，已完成项保留。原件未补齐时不把不完整库导出成新的“完整备份”或新配对组。

## 验收边界

本机代码、公开向量、范围／非授权解密、真实 Linux SQLCipher／Blob 换钥及分层恢复为本轮验证范围。Android 真机强生物识别、手机 Argon2id／大包内存、Windows 编译运行、正式签名、安全外部复核仍待后续；云端与语言／视觉优化由人类明确后置。内部工程格式可以继续演进，不扩大旧 evaluation suite，也不冻结为第三方公共契约。
