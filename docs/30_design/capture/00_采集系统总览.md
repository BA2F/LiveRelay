## 首版输入与完整整理链路

首版允许直接输入文字，拍照或从相册选取照片，以及录音、录像。文字、照片、录音和录像都需作为原始资料进入加密保存，并在资料列表中可见；不能因为暂时没有自动识别能力就丢弃音视频原件。

目前要求完整跑通的自动识别链路仍以照片为主：

```text
照片 / 相册导入
→ 原图进入加密保存
→ 本地 OCR
→ 文本 + Bounding Box
→ 用户按 OCR 行标记敏感字段
→ AI Privacy
```

录音、录像首版先满足采集、加密保存和回看原件；语音转文字、视频内容提取及其自动整理留到后续。手动文字无需 OCR，可直接进入整理草稿流程。音视频原件将来产生的文本或卡片仍需追溯到原件及相应时间片。

PDF/文档导入、ASR 与视频内容识别不阻塞首版。

## 边界

- Capture 负责获得输入和人工标注；
- OCR 负责图片 → 文本与坐标；
- Capture 不决定释放权限；
- Capture 不定义 Revision；
- AI Privacy 只消费 Capture 已产生的标注/文本，不重新定义人工标注类别。

## MVP 实现结论

- 媒体先读取并写入加密 Blob，成功后才登记 Vault 元数据和来源卡片；
- 图片、录音和录像共用 AES-GCM Blob，单文件上限 256 MB；
- 采集插件产生的临时文件在导入成功或失败后清理，启动时再清理已知缓存；
- Capture 是表现层用例，OCR 通过 `OcrProvider` 独立于采集插件和 AI Privacy；
- 失败保留已成功保存的原件，不因 OCR/AI 失败删除原始资料。

## 2026-10-03 本地语音

正式版软件基础新增本地 SenseVoice 安装、录音／WAV 导入及文字核对页。原件先加密保存，识别失败仍保留，确认文字关联原件保存为待整理草稿；未向云上传音频。Linux 真实模型和公开样本识别通过，手机资源／录音与 Windows 运行仍待验证，细节见 [本地语音输入](03_本地语音输入.md)。首版“ASR 后置”说明保留为历史阶段范围。

## 2026-10-12 采集只留一个保存动作

一次采集只有一个保存动作：拍照、录像、导入文件选中即加密保存；录音和「记一条」按下保存即落库。转写、OCR、AI 整理都属于保存之后的独立动作，各自的结果再单独存为待整理草稿，不与采集时的保存混在一起。手机上的录音入口同时承担语音输入（2026-10-03 的独立入口已并入），细节见 [本地语音输入](03_本地语音输入.md)。
