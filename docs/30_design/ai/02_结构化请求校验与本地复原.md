# 结构化请求、校验与本地复原

> 最后更新：2026-09-23

## AI 请求

MVP 请求中明确：

- Prompt；
- Schema；
- Context；
- Provider metadata。

OpenAI-compatible 请求使用低温度和 `json_object` response format。System Prompt 明确把 `user_data` 视为不可信数据而非指令，并要求 Token 原样、恰好出现一次。

## AI 返回

首版逻辑 Schema 为：

```json
{
  "cards": [
    {
      "title": "string",
      "content": "string",
      "kind": "note|account|asset|debt|location|relationship|document|wish|familyOperation",
      "inference": false
    }
  ]
}
```

返回以 `inference` 区分明确内容和推断；所有结果写成 `AI / 待确认` 草稿，推断项另加 `推断` 标签。当前不要求模型提供逐字段来源引用。

- 事实；
- 推断；
- 来源引用。

## 本地校验

至少校验：

- Schema；
- 类型；
- 未知字段；
- 非法 Token；
- 缺失 Token；
- 重复 Token。

## Rehydration

Token Map 只在本地使用，云端不获得映射表。

只有通过校验的结构化结果才能在本地执行 Rehydration。

校验会拒绝顶层/卡片未知字段、错误类型、不允许的 kind、空内容、超过 200 字标题、空卡片列表或超过 20 张卡片。任意未知、缺失或重复 Token 都使整次返回失败；不会做部分 Rehydration。AI 可以拆分/组织文本，但不能在校验层静默丢弃任何敏感 Token。

## 当前开放问题

- 非敏感原文被模型遗漏时，当前没有与 Token 同等级的确定性完整性检查；
- Schema 合法但语义错误仍需人工确认；
- 更细的字段级来源引用和模型/请求 metadata；
- 多 Provider 的原生 Structured Output 差异。
