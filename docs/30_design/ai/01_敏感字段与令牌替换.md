## 字段来源

首版直接消费 Capture 的人工标注：

- Account
- Secret
- Money
- Note

不在本文重新定义这些类型。

首版依赖人工 OCR 行标记，不追求自动 NER；本地自动识别属于后续能力。

## MVP Token 规则

实际形式：

- `[[ACCOUNT_01]]`
- `[[SECRET_01]]`
- `[[MONEY_01]]`
- `[[NOTE_01]]`

Token 需要：

- 在当前处理上下文中唯一；
- 可校验；
- 不泄露真实值；
- 可以被本地 Token Map 可靠复原。

Token 作用域只限单次用户授权的调用；每类独立编号 01～99。整条标记行替换为一个 Token。Token Map 只存在于本次本地处理对象中，不写数据库、不发给 Provider。

## 云端可见边界

默认不上传：

- 原始照片；
- 原始音频；
- Secret 原文。

如果未来提供用户主动选择的高准确率云模式，应另行风险提示。

Provider 返回必须保留每个期望 Token 恰好一次；未知、缺失或重复 Token 都拒绝整次复原。

## 当前开放问题

- 从整行标记升级到字符区间或自由区域后的 Token 粒度；
- 非敏感文本的确定性遗漏检测；
- Dart GC 环境中 Token Map 和复原字符串无法保证立即物理清零；
- 一次调用超过同类 99 个敏感字段时的分批交互。
