# 接口总览

> 状态：已确认\
> 版本：0.11\
> 最后更新：2026-10-03\
> 依赖文档：无


当前已经存在可替换的 **MVP 内部端口**，但仍没有面向第三方或跨 package 冻结的公共契约。真实 Dart 类型以 `work/code/live_relay/lib/core/ports/` 为准。

| 内部端口/边界 | 当前输入输出 | 实现与状态 |
|---|---|---|
| `VaultRepository` | 卡片、修订、来源、关联原件、回收/恢复、Blob 元数据、凭据、策略、状态、统计和备份导出审计的异步读写 | `SqliteVaultRepository`；已在 App 使用 |
| `OcrProvider` | image bytes + original name → `OcrResult` | Google ML Kit 中文 OCR；Android 已验证 |
| `AiProvider` | 连接配置 + 协议 + 脱敏文本 + 取消信号 + 本次已授权的可选隔离命令会话 → 结构化候选文本 | Chat／Responses；工具循环测试通过，真实服务待联调 |
| `AgentCommandProvider` | 能力探测／脱敏输入 → 临时命令会话；关闭／结果历史 | Linux bubblewrap 原生验证；不会回退宿主 shell |
| `SpeechProvider` | 安装状态／下载进度／导入／移除／WAV → 本地文字 | SenseVoice + sherpa_onnx；Linux 真模型通过 |
| `BiometricKeyStore` | v1 兼容：availability / save VMK / read VMK / clear | 只供旧 Header；实体设备待验证 |
| `DeviceFactorProtection` | 能力／上下文绑定的 B 封装与解封／按引用删除／取消 | Android 原生 CryptoObject；v2 设备 suite；桌面不支持，真机待验证 |
| AI Privacy Core | OCR lines + marks → redacted text/token map；response → validated drafts | 纯 Dart；Token 完整性测试通过 |
| Vault Key/Blob/Archive 格式 | 默认 Header v1，v2 内部评估 reader；Blob v1、`.lvault` v1 | 旧格式已落盘使用；v1 归档拒绝 v2 Header；新正式格式尚待验收 |

## 2026-10-02 内部演进

同 package 新增 `CardSource` 与 `BackupPreview`、来源/原件关联查询及回收恢复方法。Application 的页面搜索是完整解锁快照的投影；备份核对先验证容器、口令和数据库，再展示范围及替换影响。成功导出记录复用审计表，仅表示文件保存成功。

`application/release_preview.dart` 统一策略选择、接收者预览和模拟输出，保留原有六级释放规则，包括卡片正文前 80 个 UTF-16 单元的基本信息和凭据完整内容的备注/账号回退。不新增摘要或字段授权契约。数据库 schema v4、Header/Blob v1、`.lvault` v1 均保持兼容。

## 2026-10-03 内部呈现边界

InformationCard 为 LifeCard 与 CredentialEntry 提供共同基础字段。Application 生成不持有 Secret 的 CardSummary，保留 card／credential 身份用于打开专门详情与原有授权；统一卡片搜索不索引密码字段。CardBrowserBuilder 只接收摘要与打开回调，不接收 Repository 或 VMK。AppearanceTokens 为内部 ThemeExtension；这两个接口尚不是可分发第三方皮肤的公共契约。

AppPreferences 只存设备外观、文字大小和首次设置标记，不存身份权限或密钥；DeviceCapabilities 给 UI 明确的能力状态。现有 VaultRepository、AI／OCR／生物识别端口签名和持久格式保持不变。

## 2026-10-03 恢复事务内部边界

同日 K0 新增内部 `RecoverableFile` 与 `VaultRestoreTransaction`，提供可恢复写入、目录安装／启动处理及阶段故障注入。`AppController` 增加恢复提示与内部测试 checkpoint，密码／生物识别仍为任一路径。既有端口、数据库 schema、Header／Blob／`.lvault` 版本不变；本地操作日志不进入导出，也不冻结为对外公共 API。

## 2026-10-03 会话／备份内部边界

VaultSession 拥有会话密钥及 Repository 生命周期；VaultBackupService 仅向控制器回调清除／刷新解锁投影，回调不携带 VMK。新增 VaultBlobStore 以现有 read／write／delete 签名包住加密原件存储；原有端口签名与磁盘格式保持不变。OpenVaultRepository 为内部数据库创建函数，可在测试替换，生产仅在 app_composition 组装 SQLCipher 实现。

AppController 构造改为具名依赖注入；main／真实存储测试从 createAppController 组装。UI 原有操作方法保留，sessionState／header／biometricAvailable／recoveryNotice 改为只读投影，Widget 替身自行提供模拟状态。上述接口仅服务当前 package，未冻结第三方契约。

## 2026-10-03 K1 内部评估边界

VaultHeaderV2 的 createForEvaluation 仅产出规范 Header 字节，不自动落盘／迁移；unlockPassword／unlockRecovery 在完整 Header MAC 成功后才返回内部 VMK。RecoveryCredential 只向调用方给 LRR1 文本或用途派生密钥，dispose 清理可控字节。VaultKeyManager 元数据增加可选 formatVersion／recoveryEnabled，reader 支持严格 v2，原 create 仍写 v1。VaultSession 的内部恢复不向页面／AI 暴露 VMK，没有新 UI 按钮。

`.lvault` v1 不接受 v2 Header，setBiometricEnabled 的 v1 裸 bool 更新不能用于 v2；新设备路径尚待 K2。evaluation suite 与资源预算、精确字节见 [工程规格](../30_design/security/08_Header_v2底层格式与恢复编码.md)，未宣布公共稳定协议／正式默认 writer。

## 2026-10-03 K2 内部设备边界

DeviceFactorProtection 的能力包含强生物识别、每次授权和录入失效条件，context 只携带随机 reference 与 AAD。WrappedDeviceFactor 仅包含 12/32/16-byte nonce／密文／tag。AndroidAdapter 无旧 VMK store 调用；VaultSession 对 v2 reader 只使用新端口，VMK 返回前认证整 Header，关闭时取消并拒绝迟到结果。新 suite、profile 与失败类型见 [设备规格](../30_design/security/09_设备因素保护与Header设备分支.md)。v2 设置变更仍禁止裸 bool 写入，待 K3 认证重封装入口。

## 2026-10-03 软件基础内部边界

AiProviderRequest 新增显式协议、取消信号和可选 AgentCommandSession。命令会话只接受已授权脱敏文本，不持有 Key／Token Map／Vault；缺少会话时不发布 run_command。DraftAgentService 管理会话关闭和 Token 校验，SpeechService 管理安装与串行操作，控制器不持有原生模型指针。

VaultRepository 增加 AI 来源整批草稿保存，并为原件衍生卡片提供可选来源类型／标签，保留旧调用默认行为；语音草稿使用 audio 来源并关联原件。上述均为同 package 内部演进，没有 schema 或公共格式升级。

## 当前契约规则

- UI 和具体 Provider 不能绕过 Application 直接读取 VMK；
- AI Provider 只接收调用方提供的脱敏文本，不获得数据库、原图或 Token Map；
- OCR 只产生候选结果，不决定事实状态或释放权限；
- 所有持久化调用为异步，Repository 负责修订历史和审计写入；
- Blob、Vault Header 和 `.lvault` 格式必须显式版本化，不能用依赖库私有格式替代产品格式；
- 新客户端出现前，端口允许在同一 package 内演进；一旦跨 package 复用，需冻结错误语义、兼容性和契约测试。

## 何时创建独立公共契约文件

一个公共契约至少明确以下内容后才创建独立 Markdown：

- 目标和非目标；
- 输入/输出及类型；
- 错误语义；
- 同步/异步要求；
- 生命周期/幂等性要求（如适用）；
- 安全与隐私约束；
- 版本和兼容性；
- 最小契约测试。

当前端口已有真实实现，但尚未达到对外公共 API 的兼容承诺；不要仅复制 Dart 签名制造两套事实源。

## 2026-10-03 本机流程内部边界

VaultRepository 增加加密本地状态读写、事务内原始数据库快照导出／带严格列名及关联核验的导入；schema v5 的 local state 不经偏好／AI 输出。VaultBlobStore 增加认证解密后重新加密的 copyUnderKey，原件 ID／路径不变。

VaultSession 增加 v3 日常认证及受限 recovering 状态、临时克隆钥的受控服务回调、操作代次取消；AppController 提供创建／回输、日常／独立恢复、全库安全设置、配对备份和补齐用例，不把 VMK 返回 UI。安全设置图和新包格式分别见安全10／11。

LocalHandoffService 接收明确的 ScopedRecord（类型、ID、级别、另行历史及原件ID），生成公开身份、挑战／响应和本次限定快照；RecipientService 接收签名加密 wire，自己拥有独立身份及目录，不接受 Owner Session／Repository／VMK。DevelopmentControls 只是独立构建可注入的激活端口；生产不注入具体控制器。可选 clock 与能力矩阵不影响密码学授权。

新入口均为同 package 内部 API，未形成跨 package 稳定承诺；旧 Header／备份 reader 保留，演进格式不复用旧 evaluation suite。
