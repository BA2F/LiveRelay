当前 MVP 在单个 Flutter package 中完成逻辑模块划分。下表描述 **as-built 归属**；“已实现”不表示已经拆成独立 package，也不表示接口已冻结给第三方。

| 逻辑组件/能力 | 当前职责与代码归属 | 物理状态 | 契约状态 |
|---|---|---|---|
| UI | `presentation/`：Material 3 页面、对话框、Design System atoms | 已实现 | 无公共 UI 契约 |
| Application | `AppController`：页面快照／搜索及业务投影；`VaultSession`：会话／密钥；`VaultBackupService`：核对／恢复；`release_preview.dart`：释放投影 | 已实现 | App 内部 API |
| Life Core | `core/domain/`：卡片、凭据、原件、状态和策略语义 | 已实现 | 纯 Dart 内部模型 |
| Vault | `VaultRepository` + `SqliteVaultRepository`：结构化数据、策略、历史、来源、回收/恢复、备份导出审计 | 已实现 | MVP 内部端口 |
| Crypto | `core/security/`：Argon2id、VMK 封装、中文词组口令 | 已实现 | 主流程 Header v3，兼容 v1／v2 reader；内部格式未对外冻结 |

## 2026-10-03 正式版基础

同一 package 新增 InformationCard 共同抽象、CardSummary 安全摘要、AppPreferences 设备偏好和 DeviceCapabilities 内部状态表。UI 新增首次设置、我的、宽屏侧栏；AppearanceTokens 与 CardBrowserBuilder 提供主题和档案浏览器的内部替换点。凭据保留原有表与 recordType，schema／备份格式不变。Linux 原生端到端回归通过；该基础切片交付时 Agent 运行时、恢复密钥与在线服务尚未实现，后续实现见本文件 K1／K2／软件基础记录。

## 2026-10-03 恢复事务

同日 K0 新增 `core/storage/recoverable_file.dart` 与 `infrastructure/backup/vault_restore_transaction.dart`，分别负责 Header 前序副本与本地恢复意图／提交／启动处理。Application 在恢复后核对生物识别启用状态，避免读取残留设备 VMK；没有改变加密／归档格式或新增独立恢复钥匙。模块仍在同一 package，事务记录不是公共备份契约。

## 2026-10-03 会话／备份应用服务

`application/vault_session.dart` 接管会话状态、VMK、密码／指纹、数据库生命周期和原件访问；`application/vault_backup_service.dart` 接管认证备份核对、导出和恢复工作流。AppController 保留页面状态与业务投影。`infrastructure/app_composition.dart` 为 main 与原生测试组装默认实现，存储使用可注入 Repository 工厂及新增内部 VaultBlobStore。原 EncryptedBlobStore 实现该端口，算法和文件格式不变。

## 2026-10-03 K1 底层评估

`core/security/vault_header_v2.dart` 实现受限双分支 OR 与整 Header MAC，`recovery_credential.dart` 实现独立随机 LRR1，`header_encoding.dart` 固定受限规范字节；`VaultKeyManager` 兼容 v1/v2 读取且默认仍写 v1。VaultSession 新增仅内部恢复路径，新格式设备设置在读写旧槽前拒绝；归档 v1 拒绝包入／暂存 v2 Header。界面、新备份、设备因素及正式 profile 验收尚未完成。工程格式见 [内部规格](../30_design/security/08_Header_v2底层格式与恢复编码.md)。

## 2026-10-03 K2 设备因素

新增 DeviceFactorProtection 内部端口、AndroidDeviceFactorProtection 通道适配和原生 DeviceFactorChannel；原生每次强生物识别授权仅保护 B，不存 VMK。VaultHeaderV2 增加独立设备 evaluation suite，VaultKeyManager／VaultSession 接通新格式指纹，v1 仍走原 store，关闭后迟到设备结果拒绝。默认 writer、设置重封装及备份路径未切换；真实设备未验收。见 [设备规格](../30_design/security/09_设备因素保护与Header设备分支.md)。

## 2026-10-03 软件基础

密码库新增安全随机密码生成与选用；Agent 与 Speech 的主要逻辑进入独立应用服务和适配器，控制器做状态接线。AI 草稿整批保存保留原始文字来源，语音草稿保留加密录音关联，schema／Header／Blob／备份格式不变。Linux 命令适配只处理已许可脱敏文本，不获得 Repository 或 VMK。见 [Agent](../30_design/ai/05_内置Agent与隔离命令.md)与 [语音](../30_design/capture/03_本地语音输入.md)。

## 进一步拆成独立 package 的条件

只有具备以下多数条件后才拆分 package 或新增详细模块文档：

- 职责和非职责已经明确；
- 上下游关系明确；
- 已出现第二个客户端或独立复用需求；
- 关键输入输出已经足够明确；
- 可以独立测试或独立替换；
- 能够给 Agent 清楚的修改边界。

当前不为已在代码中清晰表达的目录机械复制说明文档。跨模块格式、稳定契约和安全边界仍应写回正式设计。

## 2026-10-03 本机完整流程映射

- `VaultHeaderV3`／`OwnerCrypto`：独立 OR／AND／Recovery 图与严格认证；旧 evaluation suite 保留。
- `VaultSecurityService`：安全设置／恢复受限会话、数据库状态复制、VMK 轮换、原件重加密与 K0 安装；不由 UI 拼接 Header。
- `VaultBackupService`／`LifeVaultArchiveService`：v1／v2 完整包、配对分层包、缺失状态与补齐；暂缺原件的旧 Blob 钥仅保存在加密数据库。
- `LocalHandoffService`／`LocalIdentity`／`LocalHpke`：所有者加密资料、独立身份、指纹及双钥证明、精确快照和签名 HPKE 包；不使用模拟生活状态赋权。
- `RecipientService`：独立目录及密码、身份备份、Owner 信任／高水位／密文包、只读显示；不依赖 VaultSession。
- `main_debug_demo.dart`／`development/`：只由独立启动入口引用的模拟控制器和虚构资料；默认 main 无此依赖。

仍是同一 Flutter package 中的明确职责，没有宣称已拆 package 或冻结第三方协议。
