# Windows 桌面适配验证

> 状态：本轮实施与回归完成，未发布制品
> 日期：2026-10-18（Asia/Shanghai）
> 分支：`codex/windows-adaptation`，起点 `8d887b6`（`origin/main`）
> 宿主：Windows 11（10.0.26300），Flutter 3.47.7 stable／Dart 3.13.5，Visual Studio 2022 C++

## 起点

远端已把 `codex/desktop-rebuild`、`codex/desktop-workbench`、`codex/formal-foundation` 合并进 `main` 并删除，`main` 现在只有一条线（`8d887b6`，v1.0.0-beta.2 之后）。这条线**没有** Windows 修复：`lib/core/storage/file_commit.dart` 不存在，6 个文件共 13 处仍直接调用 `rename`。

10-14 的移植建立在当时的 `codex/desktop-rebuild` 上，分支已不存在。本轮把同一份修复重新落到 `main`：这些文件在 `dc5fbe0`（10-14 的基线）与 `8d887b6` 之间没有变化，所以代码与用例直接沿用，文档按新 main 重写。

## 缺陷与根因

带 EFS Encrypted 属性的 `%APPDATA%`／`%LOCALAPPDATA%` 拒绝 Dart 的元数据重命名，`File.rename` 报 `errno 17`（`ERROR_NOT_SAME_DEVICE`），首次设置保存偏好失败，界面只显示“无法保存设置，请重试”。Win32 原语在该卷上同样退不了：`ReplaceFileW` 与 `MoveFileExW`（REPLACE_EXISTING）失败，只有 `MoveFileExW`（含 COPY_ALLOWED）成功，也就是 Windows 自身只能复制加删除。

本轮发现这台机器的 `%APPDATA%\Roaming` 已经不再加密（`cipher` 显示 `U`），10-14 那套 EFS 条件在本机消失。退化路径因此改用跨卷重命名来复现：C: 的临时文件改名到 E: 时报 **error code 17**，与 EFS 场景是同一个错误码。`commitFile` 在这种情况下降级为覆盖写入并删除 sidecar，`commitDirectory` 递归复制后删除暂存目录，实测均成功。

## 修改

新增 `lib/core/storage/file_commit.dart`：`commitFile`／`commitDirectory` 先尝试原子 `rename`，仅在平台拒绝且 sidecar 仍在时退化。目录提交拒绝覆盖已存在目标，恢复事务 7 处搬迁的目标此前都已探测为不存在。

| 文件 | 处数 | 用途 |
|---|---|---|
| `core/storage/recoverable_file.dart` | 1 | Header、接收者身份、恢复日志的可恢复写入 |
| `infrastructure/backup/vault_restore_transaction.dart` | 7 | 恢复事务的原库／暂存／回滚目录搬迁 |
| `infrastructure/blob/encrypted_blob_store.dart` | 2 | 加密原件写入（含 `writeCiphertext`） |
| `infrastructure/persistence/file_device_preferences_repository.dart` | 1 | 设备偏好 |
| `infrastructure/speech/local_sense_voice_provider.dart` | 1 | 本地语音模型安装 |
| `infrastructure/transfer/directory_transfer_medium.dart` | 1 | 目录介质（U 盘／局域网／WebDAV 挂载盘）写入 |

用例侧：恢复事务的 13 项崩溃安全用例改用 `FLUTTER_ROOT` 下 SDK 自带的 `dart`（Windows 的 `dart` 是 `.bat`，只能由 shell 解析）；2 项只在 Linux 播放后端启用的 PDF 预览用例按平台跳过；新增 `test/core/file_commit_test.dart` 与 `integration_test/windows_vault_creation_test.dart`；WebDAV 死链用例的超时从 2 秒提到 15 秒——本机对任意关闭的环回端口要约 2.0～2.1 秒才返回“积极拒绝”，原超时会把它误报成超时，断言本身不变。

`file_commit_test` 新增的跨卷用例默认跳过，指向另一块磁盘上的可写目录时运行：

```powershell
flutter test test/core/file_commit_test.dart --dart-define=LIVERELAY_SECOND_VOLUME=E:/LiveRelayProbe
```

## 验证结果

| 检查 | 结果 |
|---|---|
| `flutter analyze` | 无问题 |
| `flutter test` | 317 通过、7 跳过、0 失败 |
| `flutter test integration_test/windows_vault_creation_test.dart -d windows` | 通过 |
| `flutter build windows --release` | 通过 |
| 跨卷退化（`LIVERELAY_SECOND_VOLUME`） | 4 项全部通过 |

Windows 生产入口用例在 `%APPDATA%\liverelay-windows-verification` 下用真实 Windows 应用跑完首次设置：偏好写出、`onboardingStarted` 生效、Header `formatVersion` 为 3、`vault-header.json` 与 `vault.sqlite` 存在、`lastError` 为空，最后进入桌面工作台。

同一条命令在 10-14 的基线上是 16 项失败（13 项恢复事务子进程、2 项 Linux PDF 预览、1 项 WebDAV 死链）；本轮这些文件内容没有变化，失败原因与修法一一对应。
