## 这个版本是什么

三块内容：Windows 桌面可用性修复；本机交接改为长期密码只读视图，同时保留远程／云端身份交接；交接内容与接收者添加的补全。

### Windows

- 修复 Windows 上无法创建资料库：EFS 加密的 `%APPDATA%`／`%LOCALAPPDATA%` 或跨卷移动会拒绝元数据重命名，文件与目录提交改为先尝试原子 rename、失败后回退到覆盖写入并删除暂存文件。
- 目录提交在 rename 之前检查目标是否存在。POSIX 的 rename 会覆盖已存在的空目录，原来的顺序在 Linux 上会静默违反“目标必须不存在”的契约。
- Windows 界面统一使用 Microsoft YaHei UI，避免 Segoe UI 无中文字形时同一行混用两套字面。
- Windows 11 的 debug／release 构建、启动与生产入口首次建库已在 Windows 本机验证。没有附带 Windows 二进制，需要从源码构建（Visual Studio“使用 C++ 的桌面开发”工作负载）。

### 本机交接

- 交接准备页勾选交付内容并设置一个长期交接密码；接收者在同一台设备的锁定页输入密码查看只读快照。本机视图写入 `live_relay/handoff-view.json`，密码经 Argon2id 派生，整份视图用 AES-256-GCM 加密，文件中没有标题、正文或姓名明文；更换密码会重写文件，旧密码随即失效。Owner 资料库保持锁定。
- 勾选的卡片交付完整正文；勾选的密码条目交付标题、账号、网址、备注和当前密码。卡片可再勾选“附带原件”，所选原件随视图一起加密，总量上限 64 MB。
- 解锁页保留接收者入口：没有身份时可直接创建，已有身份时可打开此前接收的只读资料包。

### 远程／云端交接

- 交接准备页恢复“远程接收者”入口，重新接上导入公开身份、核对完整指纹、导出 `.lrshare` 与上传云端摇篮。云端摇篮的所有者侧绑定和预授权包上传重新可达。
- 接收者可以显示公开身份二维码。手机端所有者当面扫码添加接收者，显示名称和完整指纹确认后直接添加；桌面端保留 `.lrpublic` 文件导入与完整指纹回输。
- 原“真实限定范围交接”页改名为“远程接收者交接”。

### 摇篮

- 周期字段改成带标签的输入，不再把单位混在提示文字里。
- 云端摇篮服务已接入 SMTP 并完成真实提醒演练；服务侧邮件 Subject 修复不在应用包内，ECS 部署与邮件通道独立于本 Release。

## 安装与升级

- **Android（arm64）**：与 v1.0.0-beta.1、v1.0.0-beta.2 同签名，可直接覆盖升级，无需卸载。
- 从 MVP0.4 及更早版本升级需要卸载重装（签名不同），卸载前先导出备份。
- **Linux**：解压后运行 `live_relay`。运行依赖 GTK3、GLib、libsecret、libstdc++；AI Key 存储还需要会话 D-Bus 和已解锁的 Secret Service。录音另需 `parecord`、`ffmpeg` 和系统音频服务。
- **Windows**：本版本没有 Windows 附件；按应用 README 从源码构建。

## 验证

- `flutter analyze` 无问题；`flutter test` 332 项通过、3 项跳过、0 失败。
- Android Release APK 使用专用 release keystore 构建；`aapt2` 核对包名、versionName、versionCode 与 arm64 单架构，`apksigner` 核对 v2 签名和证书指纹。
- Linux 通过 `scripts/build_linux_ubuntu22.py` 在 Ubuntu 22.04.5 rootfs 内构建，全部 ELF 的 GLIBC／GLIBCXX／CXXABI 审计通过；最终 bundle 在同一 rootfs 的 Xvfb 中启动并保持运行，Impeller 与 media_kit 已加载，无密钥环时出现预期的 Secret Service 警告。
- 二维码做了公开身份载荷往返、组件渲染和畸形输入测试；没有真机扫码走查。
- 未验证：Windows 指纹与密钥环、正式安全复核、更多硬件与发行版、真实设备扫码。

## 已知限制

- 本机交接密码由双方共享，知道密码的人都能查看；这条路径不证明接收者身份。
- 远程与云端取件仍需要接收者身份和 `.lrshare`；远程接收者页保留旧的逐条可见级别下拉。
- 扫码只在 Android／iOS 上提供；桌面端继续导入 `.lrpublic` 文件并回输完整指纹。
- 云端摇篮服务、SMTP 与 ECS 部署独立于应用制品，不在本 Release 的附件中。
