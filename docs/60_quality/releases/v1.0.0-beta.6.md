# v1.0.0-beta.6 — 修复 Android 启动崩溃

> 状态：已发布（prerelease）
> 日期：2026-10-24（Asia/Shanghai）
> 源码：`c452d31879fbf18287d7b116bb3170da0ccf10c4`（main，annotated Tag 指向该提交）
> 内部版本：`1.0.0-beta.6+9`（Android versionCode 9）
> 基准：v1.0.0-beta.5（`a667735`，内部 1.0.0-beta.5+8）

## 这个版本修什么

beta.5 的 Android 包启动即崩溃：停在闪屏，进程随后退出。原因在依赖，不在应用代码。

## 原因

`path_provider_android` 2.3.x 改用 `package:jni` 读取 Android 的 `Context.cacheDir`。应用启动阶段第一次调用的位置是临时目录清理，此时 JNI 运行时还没初始化，进程被中止：

```
Abort message: 'JNI is not initialized. Are you trying to invoke a Java
API from Dart code too early, before 'main()' (such as during Dart
plugin class registration)?'
```

崩溃栈在 `libdartjni.so` 的 `FindClass`。模拟器和实体机在同一处崩溃，都能重复。

## 修复

`pubspec.yaml` 增加依赖固定：

```yaml
dependency_overrides:
  path_provider_android: 2.2.23
```

2.2.x 走 MethodChannel，不经过 JNI。`jni` 与 `jni_flutter` 已从依赖树以及 Linux、Windows 的插件清单一并移除。

构建 Android 包时用 `flutter build apk --release`，不加 `--no-pub`。加 `--no-pub` 时工具不会按 release 模式重写 `GeneratedPluginRegistrant`，装出来的包缺插件注册，启动只显示「无法打开留灯」。

## 影响范围

beta.1 到 beta.5 的 APK 都带 `libdartjni.so`，走同一条启动路径。beta.2、beta.4、beta.5 已确认带同一个库；是否每个旧版本都崩溃没有逐个验证。此前的 Android 验证使用调试入口，没有覆盖正式包的冷启动。

- 已验证：x86_64 模拟器。修复前启动即 `SIGSEGV`；修复后启动到欢迎页，进程存活，无崩溃。
- 已验证：`flutter analyze` 无问题；`flutter test` 339 项通过、3 项跳过、0 失败。
- 已验证：APK 元数据 — versionName `1.0.0-beta.6`、versionCode 9、minSdk 24、targetSdk 36、arm64 单架构、v2 签名；证书 SHA-256 为 `7dee1b1faa8904777869b634f5fc2e50cfe4acb32e09543201476d8e14531cc7`，与 beta.1 到 beta.5 相同。
- 已验证：Linux 通过 `scripts/build_linux_ubuntu22.py` 在 Ubuntu 22.04.5 rootfs 内构建，ABI 审计通过；bundle 在 Xvfb 中运行 20 秒未退出。
- 已验证：实体机冷启动。小米 13（Android 13）安装本版本正式包后启动到解锁页，进程存活，无崩溃。
- 未验证：解锁、建立资料库和交接流程的界面走查。

## 安装与升级

- 从 beta.5 覆盖升级即可，签名相同。
- beta.5 在 Android 上不可用，请升级到本版本。
- 从 MVP0.4 及更早版本升级需要卸载重装，卸载前先导出备份。
