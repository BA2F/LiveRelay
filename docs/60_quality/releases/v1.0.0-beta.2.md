## 这个版本是什么

三块内容：让手机可靠连上云端；让 Android 构建不再依赖网络；把"报平安与自动交接"（摇篮）做成可用功能。

- Android 全局放行明文 HTTP（`android:usesCleartextTraffic="true"`）。云端按本人决定用 IP + HTTP；实测确认当前 Flutter 引擎在 Android 上并不拦 Dart 层明文，本次放行是给厂商 ROM 与后续 Android 版本收紧的兼容性保险。桌面端不受影响。
- Android 构建钉版本：integration_test 插件的动态版本依赖（runner／rules／espresso 的"+"写法）钉到本地已有版本；此前网络一断（如 dl.google.com 不可达），全部 Android 构建会卡死四分钟再失败重试。
- 摇篮（报平安与自动交接）第一、二段：
  - 报平安：手动按钮为主，打开 App 自动记一次（1 小时内不重复）；记录带本人签名（Ed25519）上传云端。
  - 摇篮计划：「我的」里设定周期／提前提醒／宽限期（默认 7／1／3 天）、提醒邮箱与接收者名单，保存到云端。
  - 云端摇篮服务（配套上线于阿里云 ECS）：超过周期未报平安先邮件提醒本人；继续超过宽限期，按预先授权给接收者发取件通知（网址＋账号＋密码）。服务端打不开交接内容（端到端加密，只有接收者能解开）。
  - 手动限定范围交接新增"上传到云端摇篮"出口：选好范围直接上传为该接收者的取件包，文件名与计划、取件邮件三处一致。
  - 信任边界（本人明确接受、记录在案）：服务端掌握"何时通知"的调度权，理论上可提前通知；内容始终加密。

## 验证

- 静态分析无问题；318 项自动化测试通过。
- 手机真人实测（小米13）：连接云端（测试连接成功）、报平安（记录真实落于云端）、保存摇篮计划（真实落于云端）。
- 云端摇篮服务 ECS 干跑实测：报平安记录 6.5 天 → 提醒本人；11 天 → 取件通知；重新报平安 → 状态重置；本人真实记录的提醒演练通过（干跑日志显示提醒目标为本人邮箱）。
- 实测中发现并修复一个服务端 bug：客户卷发现逻辑不适用于 copyparty 的 `users/<客户>/` 布局（假数据放在"预期位置"掩盖了它，真机记录暴露）。修复后容器已更新并验证可发现真实记录。
- 明文 A/B 实测与证据见 `work/artifacts/cleartext-ab-2026-10-15/`。
- APK 签名证书指纹与 beta.1 一致；包名、版本、arm64 单架构经 aapt2 核对。
- 未验证：SMTP 真发信（服务当前为干跑模式，凭据就位后切换）；"上传到云端摇篮"按钮与整库搬运到云端的人工走查（相关逻辑有自动化测试覆盖）。
