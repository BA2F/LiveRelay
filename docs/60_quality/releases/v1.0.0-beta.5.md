## 这个版本是什么

修 beta.4 交接页面的两处界面错误，并修好云端摇篮服务。应用代码的改动很小，主要精力在服务端。

## 交接界面

- 打开接收者页不再在构建途中刷新界面。底层运行时同步发出变更通知，原来直接转给界面，会在构建阶段重建；现在延后一个微任务再通知。
- 「添加接收者」对话框的文本框控制器改由对话框组件自己管理。原来在对话框退场动画期间就销毁控制器，会报「used after being disposed」。取消和确认两条路径都不再触发。
- 锁定页取件弹层里，「打开交接包」加副标题「用邮件里的取件码打开」，改为「通过此软件打开交接包」，副标题删除。

## 摇篮服务（服务端，不在安装包里）

- ECS 上的摇篮容器一直是 2026-10-17 的镜像，没有 2026-10-21 加入的计划 v2 和测试邮件代码。已更新并重建。
- 数据目录从 2026-10-15 起是只读挂载，新代码写不了结果文件、删不了请求文件。已改为可写。
- 只读挂载改可写后，摇篮进程可以写客户卷。取件包不被改动的保证从挂载层降到代码层；当前代码只写 `liverelay-cradle-test-result.json`，只删 `liverelay-cradle-test.json`。
- 细节和验证见 [摇篮服务部署修复](../handoffs/2026-10-24_摇篮服务部署修复与Windows性能观察.md)。

## 安装与升级

- **Android（arm64）**：与 beta.1 到 beta.4 同签名，可直接覆盖升级。
- 从 MVP0.4 及更早版本升级需要卸载重装（签名不同），卸载前先导出备份。
- **Linux**：解压后运行 `live_relay`。运行依赖 GTK3、GLib、libsecret、libstdc++；AI Key 存储还需要会话 D-Bus 和已解锁的 Secret Service。录音另需 `parecord`、`ffmpeg` 和系统音频服务。

- Android 在 x86_64 模拟器上启动卡住，原因在 `getTemporaryDirectory()`。真机状态待确认。

- Windows 人工走查仍未做。

- 邮件仍带同一个 WebDAV 账号密码；云端为 IP+HTTP；服务端可见邮件里的取件码。这些取舍与 beta.4 相同。
