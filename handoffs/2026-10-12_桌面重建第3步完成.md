## 这一轮做了什么

外发确认模型（跨端共用）落成设备本地的授权记录：按"服务 + 本机地址"记住内容与附件两类授权。三条 AI 外发路径（桌面助手对话、Agent 整理页、原件 OCR 工作区）和远程语音上传改成同一套语义：首次向该服务发送内容、首次发送附件各拦一次，弹窗里说清"确认后以后这类默认发送"，确认后就记；日常发送不再弹窗，实际外发内容常驻在输入区上方的「将发送」面板里，所见即所发。面板显示的就是发送范围：脱敏后的文本、附件清单与核对转写、可折叠的重发历史；有标记时说清标记行以占位符发送。AI 服务设置与语音页都显示授权状态，并留了"收回授权，下次重新确认"的入口；移除服务配置会一并清掉它的授权；改地址视为新服务，重新拦一次。

可撤销动作改成就地做、顺手撤。桌面卡片「移入回收区」去掉确认框和"同时回收未共享原件"勾选：直接移入，SnackBar 给撤销（恢复卡片），原件不随卡片走。手机「记一条」编辑器的两个保存按钮收敛成一个「保存」：新内容存为待整理；编辑已确认的卡片保持已确认，和桌面自动保存一致；要确认去卡片详情的"本人确认这条内容"。不可逆动作维持原样：密码条目永久清除、整库替换恢复仍有明确确认。

手机采集流按"一个入口、一次保存"收敛。记录页只保留「录音」一个语音入口：录 16 kHz 单声道 WAV（最长 60 秒），保存原件就是采集阶段唯一的保存动作，保存后可以直接「转写为文字」，识别在已入库的原件上进行，不再另存一份音频，核对后的文字存成关联该原件的待整理草稿；原件详情的整理内容页签也新增了「转写为文字草稿」。「暂不自动转写」这句把用户推去另一个入口的提示删掉了。「我的」里的「语音输入」改名为"语音识别与转写"，它现在是模型与识别设置页，不是第二个采集入口。

死胡同提示清了一处：原件 AI 工作区原来在没有识别文字时弹"请先在本机识别文字"就结束，现在直接打开工作区，手工整理随时可用。

指纹开关那条原则（只改无关设置不得连带重输恢复凭证）本轮按本人确认走"只验主密码"的极轻路径。读 Header v3 格式后确认现有格式做不到：D = SHA256(descriptor) 覆盖全部分支与 biometricEnabled，增删设备因素会让全部分支密文失效、逐个重建，而重建恢复分支需要恢复秘密 R。因此设备因素要从凭证图解耦，属于安全格式改动；本轮不动引擎，写成 K3 任务并回写安全设计 07/08。

## 实现要点

- 新代码：`core/ai/outbound_consent.dart`（类别、目标）、`core/ports/outbound_consent_repository.dart`、`infrastructure/ai/outbound_consent_store.dart`（与 AI 服务配置同处设备存储，版本 1，识别不了的记录拒绝且按未授权处理）、`application/ai/outbound_consent_service.dart`（写入成功才在内存生效，失败保持未授权）、`presentation/dialogs/outbound_consent_dialog.dart`（首次确认闸门 + 常驻预览面板）。
- 授权键是 `ai:<profileId>@<host>` 与 `speech@<host>`；授权跟随本机服务配置，不进加密库、不随整库搬运。
- 发送前的一致性校验（本轮/代次/附件指纹/配置代次）原样保留，授权只替代"每轮弹窗"。
- `SpeechInputPage` 增加"转写已入库原件"模式（`sourceBlobId`）：不重复落库、草稿直接关联该原件；此模式隐藏重新录音，避免文本与原件错配。
- 记录页录音从 m4a 44.1 kHz 改为 WAV 16 kHz 单声道（与前语音输入一致），因为非 WAV 转码只在 Linux 可用，手机端要保持"录完能转写"。
- 编辑区布局重排：输入、标记、面板放进可滚动区，发送行固定留在窗口内（原因见下面的事故记录）。

## 现场事故与排查（本轮新增）

- 现象：desktop_workbench 套件在对话用例"卡死"，终端只剩 `Null check operator used on a null value` 或 driver 断连，应用窗口停在中途。
- 真实原因：新加的常驻面板把「发送」按钮挤出测试窗口——当次窗口 1280×720，按钮落在 y=808，`tester.tap` 判 `would not receive pointer events … outside the bounds of the root of the render tree`；集成绑定在格式化这条错误时又崩在渲染树诊断上（某个 RenderParagraph 的 text 已被清空），于是整轮挂死。
- 产品侧修复：编辑区改为内容可滚动、发送行固定可见；小窗口下不再把操作按钮顶出可视区。
- 排查方法（本轮摸索出来，下次直接用）：应用内 print 在 `flutter test`／`flutter drive` 下都不回传终端；把诊断写进文件；打印 FlutterError 时不要用 `exceptionAsString()`（会再崩一次），改用 `details.exception.diagnostics.take(n)` 逐节点 try 打印，第一节点就是真正的错误信息。
- 环境事实：桌面测试窗口尺寸随所在显示器/分辨率变化，已写进项目 memory（desktop-test-window-size）。

## 留下的东西

- 原件自身仍没有回收入口：引擎的 `previewCardDeletion`／`trashCards(recycleUnsharedOriginals:)` 能力保留，界面上没有入口；`capture/00` 里"原件删除与衍生卡片/来源链的清理策略"继续是开放问题。
- 长录音（>60 秒）与时间片转写仍是开放问题，手机上录音入口的 60 秒上限与之对齐。
- 第 4 步是 C 模式整库互通；K3（设备因素解耦、指纹开关）已立任务。
